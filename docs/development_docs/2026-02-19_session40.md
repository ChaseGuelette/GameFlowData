# Development Session 40 — 2026-02-19

## Summary

Evaluated two AST-only surgical retrains using the new `run_partial()` with per-quantile hyperparameter tuning. Individual AST calibration is good (all quantiles < 2% gap), but the combined calibration (minutes x rate) still shows a Q10 gap of 7.6% — down from 10.25% in production but still above the 5% tolerance. No model promoted. Also noted PTS and REB combined Q25 gaps exceeding 5% on the new calibration window.

## Context

Session 35 identified that the production model's AST combined Q10 gap was +10.25% — the largest calibration issue after archiving the THREES model. The root cause is zero-inflation: many players log 0 assists even when playing significant minutes, so the combined distribution (minutes x assists/min rate) accumulates excess probability mass near zero, pushing Q10 coverage well above the target 10%.

Session 40 tested whether a surgical AST-only retrain could close this gap without touching the well-calibrated PTS, REB, and Minutes models.

## Code Changes

### `train_pipeline.py` (+105 lines)

Added `_resolve_hyperparams_partial()` method to the `TrainingOrchestrator` class. This enables hyperparameter tuning for individual retrained components when using `run_partial()`, not just the full pipeline.

**Priority chain for hyperparameter resolution:**
1. Explicit file via `--hyperparams-path`
2. Fresh Optuna tuning via `--tune`
3. Base model's `best_hyperparams.json`
4. XGBoost defaults

**Before:** `run_partial()` called `pipeline.train_minutes_model(train_df)` and `pipeline.train_rate_models(train_df, stats=retrain_stats)` without hyperparams.

**After:** `pipeline.train_minutes_model(train_df, hyperparams=minutes_hp)` and `pipeline.train_rate_models(train_df, stats=retrain_stats, hyperparams=rate_hp)`.

### `monte_carlo.py` (-46 lines)

Cleanup — removed unused code.

## Analysis

### Why AST Q10 Combined Gap Persists

The core issue is **zero-inflation** in assists. Many players — especially bigs and defensive specialists — frequently log 0 assists even when playing 25+ minutes. The Monte Carlo simulation (minutes x assists-per-minute rate) generates many samples near zero, pushing the Q10 coverage well above the 10% target. This is a structural property of the stat distribution, not a model training issue.

Surgical retraining of the AST rate model alone reduced the gap from 10.25% to 7.60% — a 26% relative improvement — but cannot fully resolve a distributional shape problem.

### Why PTS and REB Q25 Gaps Worsened

The frozen PTS and REB models were not retrained, but their combined Q25 gaps got worse in the new runs. This is likely a **calibration window effect** — the new runs evaluated on a slightly different date range (up to 2026-02-12/2026-02-15 vs the production model's original window). The minutes model's coverage shifted on the new window, and the multiplicative interaction (minutes x rate) amplified small shifts at Q25.

### Hyperparameter Tuning Impact

Per-quantile Optuna tuning (Run 2) made minimal difference vs no tuning (Run 1) for AST individual calibration:
- Run 1 AST individual max gap: 1.83%
- Run 2 AST individual max gap: 1.82%

The tuning did improve the AST Q10 combined gap by 0.5 percentage points (8.10% → 7.60%), but this is marginal. The bottleneck is the distributional shape, not the hyperparameters.

## Decision

**No model promoted.** The AST Q10 combined gap of 7.60% still fails the 5% tolerance. Potential next steps:

1. **Zero-inflated mixture model** — Model assists as a mixture of a point mass at 0 and a continuous distribution for positive values
2. **Improved conformal recalibration** — The existing recalibration system applies offsets when gaps exceed 3%, but the AST Q10 combined gap may need more aggressive correction
3. **Full retrain with extended calibration window** — Address PTS and REB Q25 drift simultaneously

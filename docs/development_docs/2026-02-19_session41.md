# Development Session 41 — 2026-02-19

## Summary

Fixed CI pipeline failures caused by module-level `sys.exit()` and `raise ValueError` calls in 5 source files. These crashed pytest during test collection when environment variables (`DATABASE_URL`, `ODDS_API_KEY`) were missing or empty — which is the case in GitHub Actions CI.

## Problem

The GitHub Actions CI workflow sets env vars to empty strings:
```yaml
env:
  DATABASE_URL: ""
  ODDS_API_KEY: ""
  RAPIDAPI_KEY: ""
```

Several source modules validated env vars at **import time** and called `sys.exit(1)` or `raise ValueError` when they were falsy. Since pytest imports test files to collect tests, this crashed the entire test collection phase — no tests could run.

The error manifested as:
```
collected 184 items / 3 errors
INTERNALERROR> SystemExit: 1
```

## Root Cause Analysis

Six files had module-level validation that prevented import:

| File | Module-Level Issue |
|------|-------------------|
| `src/db/client.py` | `raise ValueError("DATABASE_URL not found...")` |
| `src/scrapers/daily_player_props_scraper.py` | `sys.exit(1)` when missing `DATABASE_URL` or `ODDS_API_KEY` |
| `src/scrapers/daily_game_lines_scraper.py` | `sys.exit(1)` when missing `ODDS_API_KEY` |
| `src/scrapers/game_lines_scraper.py` | `raise ValueError("Missing credentials...")` |
| `src/scrapers/live_odds_scraper.py` | `raise ValueError("Missing credentials...")` |
| `tests/test_db_client.py` | Test expected import-time crash (needed update) |

## Fix Applied

**Pattern: Defer validation to runtime, not import time.**

1. **`db/client.py`** — Engine creation is now conditional: `create_engine(DATABASE_URL) if DATABASE_URL else None`. The `get_engine()` function raises `ValueError` at call time if the engine is `None`.

2. **Scraper files** — Removed all module-level `sys.exit(1)` and `raise ValueError` blocks. Env var validation moved into `if __name__ == "__main__":` blocks so scripts still fail fast when run directly.

3. **Engine initialization** — All scrapers use `engine = create_engine(DATABASE_URL) if DATABASE_URL else None` pattern. The `engine` variable is `None` when env vars are missing, but tests mock it anyway.

4. **Test update** — `test_import_raises_without_database_url` renamed to `test_get_engine_raises_without_database_url` to test the new call-time validation.

## Verification

- **608 tests pass** with empty env vars (simulates CI)
- **0 collection errors** (previously 3-6 errors)
- **Ruff lint clean** across all changed files
- Scripts still fail fast when run directly without credentials

## Key Learning

Module-level `sys.exit()` and `raise` in Python libraries prevent importing the module entirely — which breaks pytest collection, IDE tooling, and any downstream imports. Validation should happen at the point of use (function calls, `__main__` blocks), not at import time. This is especially important for modules that depend on environment variables that may not be available in all contexts (CI, testing, IDE analysis).

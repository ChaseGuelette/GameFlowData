# Session 15: C4 THREES Truncated Negative Binomial Count Model

**Date:** 2026-02-09

## Summary

Implemented C4 — a Truncated Negative Binomial count model to replace the failed C3 hurdle+quantile regression approach for THREES predictions. The C3 model had a 25.6% calibration gap at Q10 because quantile regression produces continuous values for discrete integer outcomes.

## Problem Statement

Made three-pointers are discrete integers (0, 1, 2, 3...) with:
- ~35% of samples exactly 0
- Overdispersion (variance ≈ 2.8 vs mean ≈ 2.1)

The C3 hurdle model failed because:
1. Quantile regression predicts Q10=1.2, but you can't make 1.2 threes
2. Interpolation between 5 quantile points is too coarse
3. With p_zero≈0.47, Q10 maps to 5.7th percentile of positive distribution, requiring extrapolation

## Solution: C4 Architecture

### Stage 1: Zero Classifier (unchanged from C3)
- XGBoost binary classifier predicts P(threes = 0 | features)
- Isotonic regression calibration ensures accurate p_zero estimates

### Stage 2: Truncated Negative Binomial (NEW)
- `TruncatedNegBinModel` class predicts μ (mean) and α (overdispersion)
- Two XGBoost regressors predict log(μ) and log(α) for positivity
- Inverse CDF sampling produces integer counts directly
- No interpolation — samples are integers by construction

### Key Design Decisions

1. **mu/alpha parameterization**: Standard for NegBin, maps cleanly to scipy's (n, p)
2. **Log transform**: Predict log(μ) and log(α) to ensure positivity
3. **Inverse CDF sampling**: More efficient than rejection sampling
4. **Feature names stored explicitly**: XGBoost's `feature_names_in_` is unreliable
5. **THREES removed from copula**: Count model features encode minutes context directly

## Technical Notes

### Why Not Poisson?

Poisson assumes variance = mean. Made threes show overdispersion:
- Mean ≈ 2.1
- Variance ≈ 2.8

Negative Binomial allows variance = μ + α×μ², capturing this overdispersion.

### Sampling Formula

```python
# Map uniform u to truncated NegBin
n = 1.0 / alpha
p = n / (n + mu)
p_zero_nb = nbinom.pmf(0, n, p)
adjusted_u = u * (1 - p_zero_nb) + p_zero_nb
samples = nbinom.ppf(adjusted_u, n, p)  # integers >= 1
```

### Copula Integration

THREES is **not** included in the Gaussian copula because:
- Count model features already include minutes context (`player_avg_min_l5`, etc.)
- Including in copula would double-count the minutes-rate correlation
- Zero/positive split is independent of copula anyway

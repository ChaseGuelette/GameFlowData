## What Was Built

### 1. DFS Paper Trading Engine (`src/paper_trading/dfs_paper_trader.py`)

New ~900-line module that ports the TypeScript market edge logic from `dfs/page.tsx` to Python and wraps it in a paper trading system.

**Core Methods:**
- `_fetch_dfs_lines(game_date)` — Query `raw_player_props_combined` for DFS platform lines (prizepicks, underdog, pick6, betr_us_dfs). ROW_NUMBER dedup for latest snapshot, LPAD game_id normalization, over/under pivot.
- `_fetch_sportsbook_lines(game_date)` — Same pattern for non-DFS bookmakers. HAVING clause ensures both over and under odds exist.
- `_compute_market_edges(dfs_lines, sb_lines, break_even)` — Port of TypeScript exact-line-match devigging. For each DFS line, finds sportsbooks at same line value, applies multiplicative devig (`raw_prob / booksum`), averages to consensus, computes edge = `consensus_prob - break_even`. Handles padded/unpadded game_id matching.
- `_select_entry_legs(edges_df, slip_type)` — Positive edge filter, platform preference tiebreaker (UD slips prefer Underdog lines, PP prefer PrizePicks), one-leg-per-player dedup, live game exclusion (configurable via `allow_live`), top-N by edge.
- `build_entries(game_date)` — Orchestrator: fetches lines, computes edges per slip type, selects legs, returns entry dicts.
- `place_entries(entries)` — UPSERT with `ON CONFLICT (entry_date, slip_type) DO UPDATE WHERE status = 'pending'`. Deletes old legs on re-place, inserts new legs.
- `resolve_entries(game_date)` — Per-leg resolution via `player_game_stats`. Push/cancel reduces effective entry. Flex payout lookup: `payouts[legs_won]`. Status: won (multiplier > 1), partial (0 < multiplier ≤ 1), lost (0), cancelled.
- `resolve_all_pending(exclude_today=True)` — Multi-day catchup, checks `team_game_stats` availability.
- `_update_daily_log(game_date)` — Aggregates and UPSERTs daily metrics with cumulative P&L.

### 2. Database Migration (`database/migrations/003_dfs_paper_trading.sql`)

Three new tables:
- **`dfs_paper_entries`** — 17 columns, unique on `(entry_date, slip_type)`. Tracks slip metadata, legs won/lost/push/cancelled, payout multiplier, P&L.
- **`dfs_paper_legs`** — 14 columns, FK `entry_id → dfs_paper_entries(id) ON DELETE CASCADE`, unique on `(entry_id, player_id)`. Stores player, stat, line, direction, consensus probability, edge, actual value.
- **`dfs_paper_daily_log`** — 12 columns, unique on `entry_date`. Tracks daily aggregates, cumulative P&L, bankroll.

## Technical Decisions

1. **Separate from prop trading** — DFS entries are multi-leg (correlated risk) vs single-bet prop trading. Different bankroll ($500 vs $10K), different sizing (flat $10 vs Kelly), different tables.

2. **Market edge only (no model)** — The DFS paper trader uses devigged sportsbook consensus exclusively. This tests whether the market edge signal alone can beat DFS break-even thresholds, independent of our ML model.

3. **allow_live=True default** — DFS platforms allow entries on in-progress games, so the paper trader mirrors that. The dashboard toggle lets users choose.

4. **Hardcoded bookmaker lists** — SQLAlchemy `text()` doesn't support tuple expansion for `IN` clauses. Bookmaker lists are hardcoded in SQL strings matching the pattern in `get_sportsbook_lines.sql`.

5. **Flex partial payouts** — PP flex entries pay partial amounts for near-misses (e.g., 4/5 correct = 2x). This is modeled via the `payouts` dict where multiple `legs_won` counts map to different multipliers.

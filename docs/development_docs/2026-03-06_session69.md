## What Was Built

### MLB Training Pipeline (`src/models/mlb/mlb_train_pipeline.py`)

End-to-end CLI orchestrator for training MLB pitcher K models, mirroring the NBA `train_pipeline.py` architecture.

**10-Step Pipeline:**
1. Load training data (`get_training_dataset()` + `enrich_with_matchup_features()`)
2. Load calibration holdout data
3. Per-quantile feature selection via `ImprovedFeatureSelector`
4. Optional Optuna hyperparameter tuning
5. Train XGBoost quantile models (Q10/Q25/Q50/Q75/Q90)
6. Calibrate on holdout (conformal offsets via `QuantileModelSuite.calibration_offsets`)
7. Generate calibration report
8. Monte Carlo sanity check on sample predictions
9. Save artifacts with atomic `_incomplete` suffix pattern
10. Finalize (rename to remove `_incomplete`)

**CLI Usage:**
```bash
python -m src.models.mlb.mlb_train_pipeline --train-seasons 2023 2024 --cal-season 2025
python -m src.models.mlb.mlb_train_pipeline --train-seasons 2023 2024 --cal-season 2025 --tune --tuning-trials 50
python -m src.models.mlb.mlb_train_pipeline --train-seasons 2024 --cal-season 2025 --cal-end-date 2025-07-01
```

**Key design decisions:**
- Calls `enrich_with_matchup_features()` explicitly (NOT included by default in `get_training_dataset()`)
- Calibration uses `QuantileModelSuite.calibration_offsets` (not separate `ConformalCalibrator` — that class is evaluation-only)
- Saves `feature_manifest.json`, `calibration_report_combined.json`, and `training_metadata.json` alongside model artifacts

### New MLB Features (28 → 31 total)

| Feature | Source | Signal |
|---------|--------|--------|
| `opp_team_k_pct_l10` | `SUM(so) / SUM(pa)` over L10 games | Opposing team K rate — normalized, not confounded by opponent quality like raw SO count |
| `opp_team_whiff_pct_l10` | Swing-weighted `SUM(whiff% * swings) / SUM(swings)` from Statcast batting | Team swing-and-miss tendency |
| `pitcher_est_bf_l5` | `3 * pitcher_avg_ip_l5 + pitcher_avg_h_allowed_l5 + pitcher_avg_bb_l5` | Estimated batters faced — K opportunity volume |

**Rationale:** The model needed to answer "K% × BF = projected Ks". `opp_team_avg_so_l10` was raw count (confounded). `opp_team_k_pct_l10` normalizes by PA. `opp_team_whiff_pct_l10` captures swing-and-miss tendency from Statcast. `pitcher_est_bf_l5` gives the model a workload/opportunity proxy.

## Key Insights

- NBA has 66 unique features, not ~200 as initially assumed. The 121 total list entries include heavy overlap (injury/rest features appear in every model list).
- MLB `get_training_dataset()` intentionally excludes matchup features — must call `enrich_with_matchup_features()` separately. This is documented in the feature catalog.
- Calibration in this codebase is handled via `QuantileModelSuite.calibration_offsets` dict, not a standalone `ConformalCalibrator` class. The `CalibrationEvaluator` in `src/models/calibration.py` is for evaluation/reporting only.

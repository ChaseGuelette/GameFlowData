**MLB Linker design decisions:**
- Mirrors NBA linker pattern but with MLB-specific adaptations (INTEGER game_id, ±1 day date window, team_id from boxscore cross-reference)
- Vectorized exact match via `.map()`, fuzzy only on unique unmatched names (cached across batches)
- Temp table UPDATE pattern for bulk writes
- Robust retry logic: 20 attempts, escalating waits (10s-60s), `engine.dispose()` on errors, survives laptop sleep/wake

**Rolling averages design decisions:**
- `shift(1)` on all stats before computing rolling windows (prevents data leakage — game N's average doesn't include game N's stats)
- Rate stats computed from rolling sums, not mean of per-game rates: `batting_avg_l10 = sum(h) / sum(ab)`, not `mean(h/ab per game)`
- Batting: 12 stats × 4 windows (L5/L10/L20/SZN) + 7 std devs at L5 + 4 rate stats at L10 + context (rest_days, games_last_7d)
- Pitching: 8 stats × 3 windows (L3/L5/SZN) + 4 derived rates at L5 (ERA, WHIP, K/9, BB/9) + 2 std devs + context (days_rest, pitch_count_last_start, starts counts)
- Reuses `rolling_with_groupby()` helper from NBA code

## What Was Fixed

### 4. Placeholder Player Names (995 Players)

**Problem:** 995 out of 3,028 players in `mlb_players` had placeholder names like "Player 542303" instead of real names. These came from a seed script, and the scraper's `_ensure_player` used `ON CONFLICT DO NOTHING`, so boxscore data never updated them. The linker couldn't match "Marcell Ozuna" from props to "Player 542303" in the DB.

**Fix (two parts):**
1. Batch-fetched all 995 real names from MLB Stats API (`/api/v1/people?personIds=...`), updated in 10 batches of 100. All 995 resolved (0 not found).
2. Changed `_ensure_player` in `mlb_stats_scraper.py` from `ON CONFLICT DO NOTHING` to `ON CONFLICT DO UPDATE` to prevent future stagnation.

**Impact:** Linker player match rate went from ~1% to 100% per batch.

### 5. Dashboard Game Times Showing "TBD" (`daily_runner.py`)

**Problem:** `_enrich_game_times()` used `utc_date = target_date + timedelta(days=1)` to find game times, assuming all NBA games happen in the evening. But matinee/afternoon games (noon-6 PM ET) fall on the **same UTC date** as the target date:
- 1:10 PM ET on March 1 = 6:10 PM UTC on March 1 (same day)
- 7:30 PM ET on March 1 = 12:30 AM UTC on March 2 (next day)

The old query only looked at UTC March 2, missing all the daytime games.

**Evidence:**
- Feb 22 (all-star weekend, lots of matinees): 36% game_time coverage
- Mar 01 (Saturday with day games): 29% coverage
- Feb 19 (all evening games, but edge case): 0% coverage

**Fix:** Changed query to search a 2-day UTC window (`target_date` to `target_date + 2`) and filter by `commence_time AT TIME ZONE 'US/Eastern'` cast to the target date. Used `CAST()` instead of `::` for SQLAlchemy parameter compatibility.

**Backfill:** Updated 2,073 existing predictions with correct game times. All 14 recent dates now at **100% game_time coverage** (was as low as 0%).

## Linker Performance Iterations

The linker went through several optimization iterations during this session:

1. **Initial version:** Per-row fuzzy matching — 3,020 players × 50K rows = too slow
2. **Vectorized rewrite:** `.map()` for exact match, fuzzy only on unique unmatched names, cached across batches
3. **Infinite loop fix:** Added `AND r.game_id IS NULL` guard to game_id UPDATE, changed break condition to `if p == 0`
4. **Pandas dtype fix:** Fuzzy cache returning all None values conflicted with float column — only assign non-null results
5. **Retry logic:** Connection drops from laptop sleep. Added 20-retry loop with escalating waits and `engine.dispose()`
6. **Batched VALUES attempt:** Tried replacing temp tables with inline VALUES clause UPDATEs — 20x slower, reverted
7. **Final version:** Temp table pattern + robust retry logic. Processes ~50K rows every 30-60 seconds.

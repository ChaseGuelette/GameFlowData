## Context

Analysis of the previous training run revealed significant minutes-rate correlation: PTS (Spearman ρ=0.314), AST (ρ=0.176). The existing post-hoc multiplicative rate adjustment in `_apply_correlation_adjustment()` used hardcoded bucket-based factors that distorted the rate distribution. A principled Gaussian copula approach was chosen to preserve both marginal distributions exactly while inducing correct rank dependency.

**New methods and functions:**
- `_predict_copula(player_id, game_id, features, stats)` — full copula sampling path:
  1. Draw shared `z_minutes` from standard normal (shared across all stats)
  2. Per-stat: generate correlated `z_rate = ρ·z_minutes + √(1-ρ²)·z_independent`
  3. Convert both to uniforms via `Φ(z)`

- `_build_extended_quantile_fn(quantile_probs, quantile_values)` — extracts quantile function construction
- `_map_uniforms_to_samples(uniforms, extended_probs, extended_values)` — inverse CDF mapping
- `compute_copula_params_from_data(df)` — module-level function computing Spearman ρ per stat
- `load_copula_params(model_dir)` — loads `copula_params.json` from artifacts

## Design Decisions

### 1. Copula vs. Multiplicative Adjustment

The legacy approach applied `rate *= factor[minutes_bucket]`, which distorts the rate marginal distribution. The Gaussian copula preserves both marginals exactly — it only controls how minutes and rates co-move. This is mathematically correct: if the minutes model says Q90 minutes = 36 and the rate model says Q90 rate = 0.65 pts/min, those quantiles remain exactly correct. The copula just ensures that high-minute samples tend to pair with high-rate samples (for PTS and AST).

### 2. Shared z_minutes Across Stats

A single `z_minutes` draw is used for all stats in a player's prediction. This ensures minutes are consistent — the same player doesn't get 35 minutes for the PTS prediction and 22 minutes for the AST prediction. Per-stat `z_rate` with different ρ values gives different correlation strengths per stat.

### 3. Backward Compatibility

Both `run_backtest.py` and `run_daily.py` use `load_copula_params()` which returns `None` if the file doesn't exist. The predictor checks `copula_params is not None` and falls back to the legacy path. This means older model artifacts (without `copula_params.json`) continue to work.

### 4. Injury Feature Temporal Safety

Injury LATERAL JOINs use `report_date <= game_date` (not strict `<`) because injury reports are published before games, and the report on game day is valid context for that game's prediction.

# Development Session 63 — 2026-03-03

## Summary

NCAAB Game-Level Prediction Pipeline — Built the entire NCAA Men's Basketball prediction stack from scratch: 3 database migrations, 3 scrapers, 4 processing modules, 3 model files, 2 orchestration jobs, scheduler integration, and 4 test files (34 tests). Game-level only (spreads, totals, moneylines) — no player props for college sports due to regulatory restrictions.

## Problem

The platform supported NBA (player props) and MLB (pitcher strikeouts) but had no college basketball coverage. NCAAB has a massive following especially during March Madness, and game-level betting markets are well-established. The goal was to build the full data pipeline, modeling layer, and orchestration to predict NCAAB spreads, totals, and derived moneylines.

## What Was Built

### Phase 1: Database Migrations

**`009_ncaab_foundation.sql`** — Core tables:
- `ncaab_teams` — 363 D1 programs (SERIAL PK, espn_team_id UNIQUE)
- `ncaab_game_schedule` — BIGINT PK from ESPN, includes neutral_site, season_type
- `ncaab_team_box_scores` — Team-level aggregated stats + computed possessions + Four Factors + opponent stats
- `ncaab_raw_game_lines` — Odds API ingest with linked columns (game_id, home_team_id, away_team_id)

**`010_ncaab_barttorvik.sql`** — Barttorvik ratings table with UNIQUE(team_name, season, snapshot_date) for point-in-time lookups.

**`011_ncaab_averages.sql`** — Team rolling averages at L5/L10/L20/SZN windows.

### Phase 2: Scrapers

**`ncaab_game_lines_scraper.py`** — Direct port of MLB scraper for `basketball_ncaab` sport key. Same parse_and_store / batch_insert pattern.

**`ncaab_cbbpy_scraper.py`** — ESPN data via CBBpy. Aggregates player-level box scores to team level. Computes possessions (`FGA - OREB + TOV + 0.44 * FTA`) and Four Factors inline. 0.3s delay between boxscore calls.

**`ncaab_barttorvik_scraper.py`** — Bulk CSV download from barttorvik.com. Flexible COLUMN_MAP handles year-to-year header variations. Retry with exponential backoff. ON CONFLICT DO NOTHING for dedup.

### Phase 3: Processing

**`ncaab_config.py`** — Rolling windows, 16 box score stats, 4 opponent stats, team alias dictionaries (partial — need expansion after first scrape).

**`ncaab_linker.py`** — Game-level linking (simpler than MLB player linker). Normalizes team names via aliases + fuzzy matching (SequenceMatcher >= 0.72). Logs unmatched names for iterative alias building.

**`ncaab_populate_averages.py`** — Shift(1) rolling team averages. Computes rest_days, games_last_7d, game_number, std_pts_l5. Full backfill (TRUNCATE) and incremental modes.

**`ncaab_barttorvik_linker.py`** — 3-step matching: manual mapping → direct name match → fuzzy.

### Phase 4: Models

**`ncaab_feature_store.py`** — ~30 game-level matchup features. LATERAL JOIN SQL for point-in-time Barttorvik ratings. Features are team differentials (home - away). Separate feature lists for spread model vs total model.

**`ncaab_trainer.py`** — Two XGBoost quantile models (spread + total). Reuses `QuantileModelSuite`. Shallower trees (max_depth=4) due to smaller dataset (~5K games/season). Derives moneyline from spread distribution.

**`ncaab_backtest.py`** — Time-travel backtester. Iterates dates, tracks ATS record, O/U record, spread/total MAE, edge metrics. Saves results CSV.

### Phase 5: Orchestration

**`ncaab_daily_stats_job.py`** — Daily pipeline: CBBpy → rolling averages → Barttorvik → linker. Season guard (Nov-Apr).

**`ncaab_lines_job.py`** — Game lines scrape + linker. Season guard.

**`scheduler.py`** — 3 new cron jobs with `month="11-12,1-4"` guard. Daily stats at 14:05 UTC, lines at 17:30 and 21:30 UTC.

### Phase 6: Tests

4 test files, 34 tests:
- `test_ncaab_game_lines_scraper.py` (5 tests) — live/historical/empty responses, sport key, batch insert
- `test_ncaab_barttorvik_scraper.py` (6 tests) — normalize, adj_em computation, four factors, dedup, fetch CSV success/404
- `test_ncaab_linker.py` (9 tests) — normalize team, closest game, fuzzy match, batch matching

## Key Design Decisions

1. **Game-level, not player-level** — Each training row is one game. Features are team differentials (home - away). No player props available for college sports.
2. **Barttorvik for adjusted efficiency** — Free alternative to KenPom. No API key needed. Updated every 15 min in-season. Point-in-time via LATERAL JOIN prevents data leakage.
3. **Neutral site handling** — `is_neutral_site` flag critical for March Madness. Home court advantage is ~3.5 points in NCAAB.
4. **Reuses existing QuantileModelSuite** — No new ML infrastructure needed. Same XGBoost quantile regression pipeline as NBA/MLB.
5. **Shallower trees (max_depth=4)** — Fewer training rows (~5K/season vs 100K+ for player props) means higher overfitting risk.
6. **Season guard on scheduler** — NCAAB only runs Nov-Apr. `month="11-12,1-4"` prevents wasting resources in off-season.

### ISS-038: Backtesting odds timestamp cutoff
**File:** `src/backtesting/backtest_harness.py`
**Problem:** `snapshot_time::date <= :game_date` includes all game-day lines at date level.
**Fix:** Changed to `snapshot_time < :game_date::timestamp + interval '23 hours 30 minutes'` for explicit 6:30 PM ET cutoff. **Functionally equivalent** given scrape schedule (12/4/6 PM ET), but more explicit about production timing.

### ISS-039: Inference data freshness check
**File:** `src/orchestration/inference_job.py`
**Fix:** Added SQL query checking MAX(game_date) in `player_average_game_stats` before generating predictions. Warns if data is >2 days stale.

### ISS-041: Batch upserts
**File:** `src/processing/populate_average_stats_incremental.py`
**Problem:** 3 upsert functions used row-by-row `iterrows()` pattern.
**Fix:** Converted to batch `conn.execute(text(sql), records)` using `insert_df.where(insert_df.notna(), None).to_dict(orient="records")`.

### ISS-042: View tiebreakers
**Files:** `sql/views/*.sql` + Supabase migration
**Problem:** `DISTINCT ON` without `game_id` in ORDER BY is non-deterministic when two games share a date.
**Fix:** Added `game_id DESC` to all 3 views. Applied via `CREATE OR REPLACE VIEW` migration.

### ISS-043: `created_at` overwrite
**Files:** `src/processing/backfill_opponent_allowed.py`, `src/processing/backfill_opponent_allowed_incremental.py`
**Problem:** UPSERT `DO UPDATE` clause included `created_at = NOW()`, overwriting original insert timestamp.
**Fix:** Removed `created_at` from update set.

## Key Learnings

1. **Audit validation is essential.** 3 of 5 "critical" findings were false positives — possessions math cancels, PKs prevent dupes, groupby handles seasons. Always validate before filing.
2. **`.sum()` vs `.mean()` in rolling windows:** When pandas rolling operates on pre-aggregated per-game data, `.mean()` gives per-game averages (correct for "allowed per game"), while `.sum()` gives cumulative window totals. The per-100 rates masked this since they divided by possessions.
3. **Backtest odds timing:** The scrape schedule (12/4/6 PM) and inference time (6:30 PM) mean all game-day lines are legitimately available at inference time. A date-level filter is functionally equivalent to a timestamp cutoff, but explicit timestamps document the production constraint.

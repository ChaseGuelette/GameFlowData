## What Was Fixed

### 1. DFS Dashboard Showing No Data (Production)

**Symptom:** Dashboard displayed "No DFS lines available" and "No sportsbook lines available yet" for both Model Edge and Market Edge modes.

**Root Cause (Layer 1):** Migration 004 (`004_fix_rpc_prediction_dependency.sql`) had not been applied to production. Both `get_dfs_lines` and `get_sportsbook_lines` RPCs depended on `daily_predictions` table for game scoping — returned nothing before inference ran.

**Fix:** Applied migration 004 via SQLAlchemy connection to production database. RPCs now scope by `commence_time` range directly.

### 2. Sportsbook RPC Statement Timeout

**Symptom:** Market Edge mode still showed no data even after migration 004. `get_sportsbook_lines(date)` was timing out through PostgREST (Supabase 8s anon timeout).

**Root Cause:** `raw_player_props_combined` is an append-only table with millions of accumulated snapshot rows (every 10-minute scrape adds thousands). The `commence_time::date` cast prevented index usage, forcing full table scans.

**Fix (multi-step):**
1. Created `idx_props_commence_time` index on `raw_player_props_combined(commence_time)`
2. Updated both RPCs to use range conditions: `commence_time >= target_date::timestamptz AND commence_time < (target_date + 1)::timestamptz`
3. Sportsbook RPC still timed out intermittently (~6.5s, close to 8s limit)
4. Created new `get_sportsbook_lines_by_games(text[])` RPC (migration 005):
   - Pure SQL function (LANGUAGE sql STABLE) for better optimizer flexibility
   - Accepts game_id array instead of date — uses `idx_props_sportsbook_lookup` (game_id first column)
   - 24-hour `snapshot_time` cutoff to limit scan
   - Returns in 0.3s for 3 games
5. Updated dashboard DFS page to two-step fetch:
   - Step 1: Fetch predictions + DFS lines in parallel
   - Step 2: Extract game_ids from DFS data, batch sportsbook queries (3 games per call, parallel)

### 3. Edge Refresh 30-Minute Timeout

**Symptom:** Railway logs showed edge refresh timing out at 22:22 UTC and 23:32 UTC on March 1, causing 3 consecutive skipped runs each time.

**Root Cause:** `fetch_fresh_lines()` query in `edge_refresh_job.py` had NO `snapshot_time` cutoff. It scanned ALL historical snapshots for given game_ids. As snapshots accumulated during the day, query progressively degraded until it exceeded the 30-minute job timeout.

**Evidence from logs:**
```
22:22 UTC - Edge refresh started
22:32 UTC - WARNING: maximum number of running instances reached (1)
22:42 UTC - WARNING: maximum number of running instances reached (1)
22:52 UTC - ERROR: Job timed out after 30 minutes: edge_refresh_job.py
```

**Fix:** Added `AND snapshot_time > now() - interval '24 hours'` to the WHERE clause in `fetch_fresh_lines()`. This matches the pattern used in the new `get_sportsbook_lines_by_games` RPC.

### 4. DFS Paper Trader Slow Queries

**Root Cause:** Both `_fetch_dfs_lines()` and `_fetch_sportsbook_lines()` in `dfs_paper_trader.py` used:
- `commence_time::date = :game_date` (prevents index usage, forces full table scan)
- No `snapshot_time` cutoff (scans all historical snapshots)

**Fix:**
- Replaced `commence_time::date` with range conditions: `commence_time >= :game_date::timestamptz AND commence_time < (:game_date::date + 1)::timestamptz`
- Added `AND rp.snapshot_time > now() - interval '24 hours'` to the latest CTE

### 5. MLB Rolling Averages pgBouncer Crash

**Symptom:** `mlb_populate_averages.py` crashed with "lost synchronization with server" when fetching game stats.

**Root Cause:** pgBouncer can't handle large single queries that take too long. Fetching the entire `mlb_player_game_stats_batting` table in one query exceeded pgBouncer's tolerance.

**Fix:** Added `_get_seasons()` helper that queries `SELECT DISTINCT season`. Modified `fetch_batting_stats()` and `fetch_pitching_stats()` to iterate seasons and `pd.concat` results.

### 6. Dashboard UX: allGamesStarted Detection

**Symptom:** When all games had started, Pre-Game filter (default) hid everything, showing a confusing empty state.

**Fix:** Added `allGamesStarted` useMemo that detects when all games have started but `showLive` is off. Renders a helpful message with clickable "+ Live" button instead of the generic empty state.

## Key Design Decision

**Why batch by game_id instead of fixing the date-based RPC:**
The `raw_player_props_combined` table is append-only — every 10-minute scrape adds thousands of rows. By the time there are 14+ games on a slate, a date-based query scans millions of rows even with indexes. Batching by game_id (3 per call) constrains each query to a small subset, and the existing `idx_props_sportsbook_lookup` index (game_id as first column) makes these queries sub-second. The 24-hour `snapshot_time` cutoff further limits the scan window.

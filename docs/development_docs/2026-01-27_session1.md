### Diagnosis

1. **No edge**: 50.9% win rate is 1.5 percentage points below the ~52.4% breakeven at -110 vig. The model is not beating the closing line.
2. **Kelly on negative EV = guaranteed ruin**: 1/8 Kelly with ~71 bets/day on a losing system compounds losses. The 99.81% drawdown is the expected outcome, not a bug.
3. **PTS is the worst performer**: Nearly half the bets, worst ROI (-8.13%). Points is the most efficiently priced prop market.
4. **REB shows possible signal**: +0.87% across 2,317 bets. Possibly real edge, possibly noise. Needs isolation.
5. **Gaussian edge calculation was creating phantom edges**: The backtester used `stats.norm.sf(z_score)` to estimate over/under probability — a Gaussian assumption applied on top of non-Gaussian quantile-sampled distributions.

## What I Shipped

### 1. Empirical CDF Edge Calculation (`src/backtesting/backtest_harness.py`)

Replaced the Gaussian CDF edge calculation with empirical CDF from the actual Monte Carlo samples.

**Before (Gaussian):**
```python
z_score = (line - pred_mean) / pred_std
prob_over = stats.norm.sf(z_score)
```

**After (Empirical):**
```python
prob_over = float((samples > line).mean())
```

Changes:
- **`_run_date()`**: Added `"samples": pred.samples` to the prediction dict so Monte Carlo samples carry through to edge calculation.
- **`_calculate_edges()`**: Primary path now uses `(samples > line).mean()` for empirical CDF. Falls back to Gaussian only if samples aren't available. Drops samples column after calculation to free memory.
- **Memory safety**: Samples column is dropped both after `_calculate_edges` and before returning from `_run_date` (belt and suspenders).

The `PropPrediction` class already had `prob_over()` and `prob_under()` methods using empirical samples — they were just never used by the backtester.

## Decisions Made

1. **Empirical CDF over Gaussian for edge calculation**: The model produces non-parametric quantile-sampled distributions. Forcing a Gaussian CDF on top systematically miscalculates tail probabilities, especially for skewed stats like assists. Empirical CDF uses the actual 5,000 Monte Carlo samples to compute `P(over)` directly.

2. **Kept Gaussian as fallback**: If samples aren't available for a prediction row (shouldn't happen in normal flow, but defensive), the code falls back to the old Gaussian path. Prevents silent failures.

3. **Sanity caps unchanged (5%-90%)**: Kept the existing probability caps. With empirical CDF, extreme probabilities are less likely to be artifacts, but caps still protect Kelly from overcommitting on edge cases.

4. **Edge threshold already existed**: `run_backtest.py` already had `--edge-threshold` (default 0.05). No CLI changes needed — just needs to be used at higher values (0.07-0.08).

5. **Analysis before implementation for assists/bimodality**: Rather than implementing ZINB or minutes mixture immediately, built a diagnostic tool first. The right fix depends on whether bimodality is real (mixture) or not (simpler adjustments).

## Evaluation of Proposed Assist Fixes

Reviewed an external analysis proposing four fixes for assist modeling. Assessment against our actual architecture:

| Proposal | Verdict | Rationale |
|----------|---------|-----------|
| **Gaussian Trap** | Partially applicable | We use quantile regression (non-parametric), not Gaussian. But the backtester's edge calc WAS Gaussian — fixed in this session. |
| **ZINB distribution** | Conceptually right, architecturally expensive | Full pipeline rewrite. Lighter alternative: binary classifier P(AST=0) mixed into Monte Carlo sampling. |
| **Minutes as mixture distribution** | Strongest, most actionable | Current blowout factor is a flat scalar. Mixture of close-game vs blowout-game minutes distributions would be better. Needs bimodality analysis first. |
| **Potential assists** | Correct but impractical near-term | Requires new data source (NBA tracking data), new scraping pipeline, retraining. Park for future. |

2. **Is REB +0.87% real edge or survivorship?** 2,317 bets at +0.87% over ~4 months. Need to check if it's consistent across the date range or concentrated in a hot streak.
3. **Should we re-derive correlation factors after empirical CDF fix?** The correlation config was tuned when edges were calculated with Gaussian CDF. The new empirical CDF path might shift which games are selected, potentially changing the optimal correlation adjustments.

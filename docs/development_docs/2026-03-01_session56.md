# Development Session 56 — 2026-03-01

## Summary

Fixed a critical bug in `fetch_fresh_lines()` where `MAX(line)` conflated alt lines from bookmakers offering multiple line values (e.g., novig at 7.5/9.5/11.5/13.5/15.5). This caused mismatched Over/Under odds, artificially low booksums, and selection of wrong lines as "sharpest." Prediction cards showed stale lines (Wembanyama at 15.5 when market was 11.5, Dort at 7.5 when market was 3.5). Same fix applied to both `edge_refresh_job.py` and `daily_runner.py`.

## What Was Fixed

### 1. `MAX(line)` Alt-Line Conflation Bug

**Root Cause:**

The SQL query in `fetch_fresh_lines()` used this pattern to collapse Over/Under rows per bookmaker:

```sql
-- BEFORE (broken)
ROW_NUMBER() OVER (
    PARTITION BY player_id, game_id, market_key, bookmaker, outcome_label
    ORDER BY snapshot_time DESC
) as rn
...
GROUP BY player_id, game_id, bookmaker, market_key
MAX(line) as line
```

When a bookmaker offers alt lines (e.g., novig has rebounds at 7.5, 9.5, 11.5, 13.5, 15.5), `MAX(line)` picks the highest. Over odds at line 15.5 get paired with Under odds at line 11.5 — these are from *different lines* and produce an invalid booksum. The artificially low booksum makes the broken row appear "sharpest," so it gets selected.

**Impact:**
- Wembanyama: stored line=15.5, market consensus=11.5 (4 rebounds off)
- Dort: stored line=7.5, market consensus=3.5 (4 rebounds off), flagged as `is_recommended=True`
- Affects all players where novig (or other multi-line books) gets selected as sharpest

**Fix:**

```sql
-- AFTER (correct)
ROW_NUMBER() OVER (
    PARTITION BY player_id, game_id, market_key, bookmaker, line, outcome_label
    ORDER BY snapshot_time DESC
) as rn
...
GROUP BY player_id, game_id, bookmaker, market_key, line
HAVING MAX(CASE WHEN outcome_label = 'Over' ...) IS NOT NULL
   AND MAX(CASE WHEN outcome_label = 'Under' ...) IS NOT NULL
```

Changes:
1. Added `line` to `ROW_NUMBER PARTITION BY` — alt lines at different values become separate rows
2. Replaced `MAX(line)` with plain `line` in `GROUP BY` — no conflation
3. Added `HAVING` clause — eliminates orphan alt-line rows missing one side
4. Sharpest-book selection (`idxmin` on booksum) now picks from correctly-matched odds, naturally preferring primary lines (lowest vig)

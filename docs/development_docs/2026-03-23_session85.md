# Development Session 85 -- 2026-03-23

## Summary

Fixed 5 data quality problems in the AI Q&A `/api/ask` route that caused the LLM to give poor, inaccurate answers. The feature was originally built in Session 83 but shipped with several broken queries and insufficient context. This session fixed the opponent defense query (missing team_id filter), added player position data, enriched teammate injuries with positions and stats, improved game log formatting to prevent row confusion, and added injury report dates.

## What Was Done

### 1. Player Position Query (replaces broken query #4)

The original parallel query #4 used an `undefined!` hack and never returned useful data. Replaced with a proper lookup from the `players` table:

```typescript
supabase.from('players')
  .select('primary_position, position_group')
  .eq('player_id', prediction.player_id)
  .limit(1)
```

Position is now shown in the system prompt header (e.g., `POSITION: Center`). The `position_group` field (Guard/Forward/Big) is also used for the opponent defense lookup.

### 2. Enriched Teammate Injuries

**File:** `dashboard/src/app/api/ask/route.ts`

Previously, teammate injuries were just names and statuses — the LLM had no way to assess the impact of an injured player being out. Now:

- Injury query includes `player_id` and `report_date`
- After deduplication, batch-looks up positions from `players` table and L15 averages from `player_average_game_stats`
- Builds enriched display: `Jaime Jaquez Jr (Forward) - Out: Knee — avg 28.3 min, 14.2 pts, 4.1 reb, 2.3 ast [reported 3/22]`

### 3. Game Log Formatting Overhaul

The dense tabular format caused the LLM to misattribute stats to wrong games (e.g., attributing 83 pts to a single game). Fixed with:

- **`#N` numbering** — Each row starts with `#1`, `#2`, etc. to anchor the LLM
- **Compact dates** — `3/22` instead of `2026-03-22`
- **Compact matchups** — `vs HOU` instead of `MIA vs. HOU`
- **New columns** — `oreb`, `dreb`, `tov`, `fga`, `fta` for efficiency and rebounding context
- **Started/Bench labels** — Instead of `Y`/`N`

### 4. Opponent Defense Query Fix

The original query was completely broken — no `team_id` filter meant it returned a random team's defensive stats. Fixed by:

1. Looking up opponent `team_id` via `team_game_stats.team_abbreviation` (the `teams` table has no abbreviation column)
2. Mapping player's `position_group` (Guard → G, Forward → W, Big → B) to `team_allowed_by_position.position_group`
3. Filtering by both `team_id` AND `position_group`

The old code also used `started` boolean to determine "Starters"/"Bench" position groups, which didn't match the actual values in the table (G/W/B/U).

### 5. Injury Report Dates

Added `report_date` to both player injury and teammate injury queries. Displayed as `(reported 3/22)` for the player and `[reported 3/22]` for teammates.

## Key Design Decisions

1. **`team_game_stats` for abbreviation lookup** — The `teams` table only has `team_id` and `team_name` (no abbreviation). `team_game_stats` has `team_abbreviation` and is the most reliable source.

2. **Position group mapping** — `players.position_group` stores "Guard"/"Forward"/"Big" while `team_allowed_by_position.position_group` uses "G"/"W"/"B". Added a constant map (`POSITION_GROUP_TO_DEFENSE`) to bridge them.

3. **4 parallel + sequential** — Reduced from 5 broken parallel queries to 4 valid ones, with teammate injuries and opponent defense remaining sequential (they depend on team_id lookups).

4. **`_position` and `_avg_stats` prefixed fields** — Enrichment data stored on the injury objects with underscore-prefixed keys to avoid collisions with actual DB columns.

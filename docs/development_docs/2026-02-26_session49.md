## Problem

### DFS Edge Modes

The DFS Edge Finder (Session 48) only showed **Model Edge** — the model's probability vs DFS break-even thresholds. Two additional perspectives were missing:
1. **Market Edge** — what does the sharp sportsbook consensus say about the DFS line?
2. **Combined Edge** — where do BOTH model AND market agree the DFS line is mispriced?

DFS platforms set their own lines that often diverge from the efficient sharp market. Comparing DFS lines against devigged sportsbook probabilities provides a model-independent signal. When both model AND market agree, that's the highest-conviction tier.

### Fallback Games

When predictions haven't been generated yet (before inference runs), the dashboard should show today's games with an empty slate. This was broken — no games were displaying. Root cause chain:
1. `get_games_for_date` RPC used `commence_time::date = target_date` cast → full sequential scan on 3.1M row table (33s) → PostgREST 8s timeout → 500 error
2. After fixing with an index + range filter, dates were wrong — UTC boundaries vs ET prediction_date convention
3. After fixing timezone, the function depended on `raw_game_lines_staging` which only has data after the odds scraper runs

## Architecture Decisions

### Multiplicative Devigging

Standard method for 2-outcome markets: `devigged_prob = raw_prob / booksum`. Equivalent to Shin's method. Same approach used in `black_litterman.py` for consistency.

### Sharpest Book Selection

For each DFS line's player/game/stat, the sharpest book is the one with the lowest `computeVig()` (booksum closest to 1.0). This is used as the reference line for line diff calculation, and its devigged probability contributes to the consensus.

### Combined Edge = min(model, market)

Conservative estimate ensures reported edge is supported by BOTH signals. If model says +8% and market says +3%, combined shows +3%. This prevents overconfidence from either signal alone.

### NBA CDN over Supabase RPC for Fallback Games

The NBA CDN schedule is always available (full season schedule, no scraper dependency) and fast. The previous `get_games_for_date` RPC depended on `raw_game_lines_staging` which only has data after the odds scraper runs. CDN is the more reliable source for "what games are happening today."

## Bugs Encountered and Fixed

1. **33-second query on `raw_game_lines_staging`**: `commence_time::date` cast prevented index usage on 3.1M rows. Fixed with range filter + index.
2. **UTC vs ET date mismatch**: Games at 7pm ET Feb 26 have UTC timestamp Feb 27. Fixed with `AT TIME ZONE 'America/New_York'` boundaries.
3. **Scraper dependency for game list**: `raw_game_lines_staging` empty before scraper runs. Fixed by switching to NBA CDN.

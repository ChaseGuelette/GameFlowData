## Design Decisions

1. **NBA API ScoreboardV2 for game discovery:** Chosen over extracting game IDs from prop lines (fragile, depends on scraping having run) or maintaining a static schedule table. ScoreboardV2 returns scheduled/in-progress/completed games and is the canonical source. 0.6s rate limit delay respected.

2. **Gzip-compressed bytea for MC samples:** 10K float64 samples = 80KB raw → ~20-40KB gzip compressed. This is small enough for PostgreSQL bytea storage while enabling arbitrary probability queries against the full distribution. Alternative (storing only quantiles) was rejected because it limits query flexibility.

3. **Empirical CDF over quantile interpolation:** `(samples > line).mean()` with 10K samples gives ~1% accuracy. The 5-point quantile interpolation was a poor approximation that could differ significantly from the true MC distribution, especially in the tails.

4. **`rapidapi_injuries` over `espn_injuries`:** The RapidAPI table uses integer `player_id` matching (reliable), while ESPN used string `player_name` matching (fragile, subject to name variation). The feature store and backtest harness both use `rapidapi_injuries`, so the daily runner now matches.

# Development Session 64 — 2026-03-03

## Summary

User Bet Tracking — Cross-Device Sync + Auto-Resolution. Built full-stack user bet tracking: SQL migration (2 tables with RLS), 2 React hooks (optimistic UI + DB sync), backend auto-resolution, and "My Bets" tabs on History and Performance pages. Replaced all localStorage-based state (taken bets, preferences) with Supabase-backed hooks that sync across devices.

## Problem

Users could click a green checkmark on PropCards to mark bets as "taken," but this was stored in browser localStorage — it didn't sync across devices (phone vs laptop). Additionally, preferences (bankroll, kelly fraction, state) were also localStorage-only. There was no way to see personal bet history or performance stats, and taken bets were never resolved against actual game results.

## What Was Built

### Phase 1: Database Migration

**`012_user_bet_tracking.sql`** — Two new tables:

- **`user_profiles`** — Per-user preferences (state, bankroll, kelly_fraction, use_custom_kelly). PK on user_id (FK auth.users). RLS policies for SELECT/INSERT/UPDATE/DELETE. Auto `updated_at` trigger.

- **`user_bets`** — User-placed bets. Unique on (user_id, game_date, player_id, stat_type). Stores full prediction context (direction, odds, book, model_prob, edge) plus resolution fields (status, actual_value, pnl, resolved_at). Two indexes: (user_id, game_date DESC) for per-user queries, partial on status='pending' for resolution batch.

Migration applied to Supabase in-session via psycopg2 direct connection (port 5432, autocommit mode — required for DDL with dollar-quoted functions).

### Phase 2: React Hooks

**`useUserBets.ts`** — Cross-device bet tracking.
- Fetches user's bets for selectedDate from user_bets on mount/date change
- Returns `{ takenBets: Set<string>, toggleBet, loading }`
- toggleBet: optimistic Set update → async upsert/delete to Supabase → rollback on error
- Auto-captures direction, odds, book, model_prob, edge from Prediction object
- Uses betRowsRef (Map) to track DB row IDs for efficient deletes

**`useUserPreferences.ts`** — Cross-device preferences sync.
- Loads instantly from localStorage (SSR-safe), then syncs from user_profiles table
- On change: writes to localStorage (instant) + DB (500ms debounced via setTimeout)
- Auto-creates profile row on first use via upsert
- Returns `{ prefs, updatePref, loading }`

### Phase 3: Dashboard Integration

**Dashboard page** — Removed ~30 lines of localStorage logic (takenBets useState, useEffect reload on date change, handleToggleTaken, userState localStorage). Replaced with `useUserBets(selectedDate)` and `useUserPreferences()`.

**AnalysisModal** — Replaced 6 localStorage reads/writes (bankroll, bankrollInput, kellyFraction, useCustomKelly, customKellyInput, userState) with `useUserPreferences()`. Added useEffect to sync input fields when preferences load from DB.

### Phase 4: Backend Auto-Resolution

**`user_bet_resolver.py`** — `UserBetResolver` class.
- `resolve_bets_for_date(game_date)` — mirrors PaperTrader.resolve_bets() logic
- `resolve_all_pending(exclude_today=True)` — multi-day catchup
- Resolution: actual > line → over wins / under loses. Actual == line → push. DNP/0-min → cancelled.
- P&L: won = stake × (decimal_odds - 1), lost = -stake

**`daily_stats_job.py`** — Added `resolve_pending_user_bets()` function called after paper bet resolution. Non-fatal: errors logged but don't fail the job.

### Phase 5: My Bets Tabs

**History page** — Added tab toggle: "My Bets" (default, green) and "Model History". My Bets queries user_bets (RLS auto-filters by user). Model History preserves existing paper_bets view with BetSourceFilter. Each tab has independent status filters.

**Performance page** — Added "My Bets" tab alongside existing "Props" and "DFS". My Bets shows:
- KPI cards (bankroll, P&L, ROI, win rate) computed from resolved user bets
- Bankroll chart (cumulative P&L from $1000 starting point)
- Stat breakdown (per-stat W/L%, ROI)

## Design Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Bet direction | Auto-capture from card's displayed direction | No UI change needed; card shows "Over 25.5", checkmark records that |
| Toggle UX | Optimistic update (instant UI, async DB write) | Must feel as fast as localStorage |
| Preferences storage | Typed columns (not JSONB) | Simpler, queryable |
| Resolution | Piggyback on daily_stats_job | Stats already available at 9 AM ET |
| localStorage migration | Skip | Old checkmarks lack direction/odds — clean break simpler |
| Tab naming | "My Bets" + "Model History" / "Props" / "DFS" | Keeps existing model views intact per user request |

# Development Session 19 — 2026-02-09

## Summary

Fixed critical off-by-one bug in feature store LATERAL JOINs and added recency filter to daily runner.

## Issues Fixed

### 1. Feature Store Off-by-One Bug (Critical)

**Problem:** The feature store queries used `< game_date` to fetch pre-computed rolling averages from `player_average_game_stats`, but this table uses `shift(1)` during population. This means the row for `game_date X` already contains averages from games BEFORE X (not including X).

**Impact:** Using `< game_date` caused queries to fetch the PREVIOUS game's row instead of the current game's row. Models were training and predicting with stale features (one game behind).

**Root cause analysis:**
```
populate_average_stats.py:
  - Computes rolling averages using shift(1) pattern
  - Row for game_date X = average of games [X-N, X-1]
  - shift(1) ensures no data from game X is included

Feature store (before fix):
  - WHERE pags.game_date < pgs.game_date ORDER BY game_date DESC LIMIT 1
  - For game X, this fetches row from game X-1
  - But row X-1 contains averages from [X-1-N, X-2], not [X-N, X-1]

Feature store (after fix):
  - WHERE pags.game_date <= pgs.game_date ORDER BY game_date DESC LIMIT 1
  - For game X, this fetches row from game X
  - Row X contains averages from [X-N, X-1] — correct pre-game features
```

**Fix:** Changed `< game_date` to `<= game_date` in 15 LATERAL JOINs across 3 methods:
- `get_features_for_date()` — backtesting
- `get_features_for_date_range()` — batch backtesting
- `_load_single_season_training()` — model training

Added explanatory comments to clarify why `<=` is safe (not data leakage).

**Exception:** Injury queries that look up OTHER players' historical stats (e.g., teammates' past performance) correctly remain as `<` since they're fetching actual past game data, not pre-computed rolling stats.

### 2. Daily Runner Returning Retired Players

**Problem:** The `_get_players_for_games()` method had no recency filter, returning players like Shaquille O'Neal and Grant Hill from historical team rosters.

**Fix:** Added 30-day cutoff filter to the query:
```sql
WHERE pgs.team_id IN :team_ids
  AND pgs.avg_min_l5 >= 10
  AND pgs.game_date >= :cutoff_date  -- NEW: 30 days before target
ORDER BY pgs.player_id, pgs.game_date DESC
```

Added `target_date` parameter to method signature for proper cutoff calculation.

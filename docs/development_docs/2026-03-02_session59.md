# Development Session 59 — 2026-03-02

## Summary

MLB Local Linker with Checkpoint/Resume — built an offline CSV-based linking pipeline for MLB that mirrors the NBA local linker pattern, with a robust checkpoint system for resuming interrupted runs.

## Problem

The existing MLB linker (`mlb_linker.py`) only works directly against the DB in `incremental` or `backfill` mode. For large backfill operations (hundreds of thousands of rows), this is fragile:
- Laptop sleep/wake can break connections mid-batch
- No way to inspect or manually fix data between stages
- No resume capability — if interrupted, the retry loop restarts the current batch but doesn't track overall progress across stages
- The NBA side already had a local linker (`nba_linker_local.py`) with download/process/upload stages and CSV skip logic, but MLB lacked an equivalent

## What Was Built

#### CLI Commands

| Command | Description |
|---------|-------------|
| `download` | Pull 6 tables to `mlb_linker_data/` (4 small + 2 batched at 100k rows) |
| `process` | Run 4 matching sub-stages locally in pandas |
| `upload` | Push results to DB via chunked temp tables (50k/chunk) |

| `status` | Show checkpoint progress + DB linking stats |
| `init` | Create `player_mappings.csv` template |
| `reset` | Clear checkpoint file |

Flags: `--force` (ignore checkpoint), `--batch-delay N` (throttle uploads)

#### Checkpoint System

`mlb_linker_data/_checkpoint.json` tracks:
- Per-stage status: `not_started`, `in_progress`, `completed`
- Download: which tables completed
- Process: rows matched per sub-stage
- Upload: chunks uploaded / total chunks per operation

Resume behavior: completed stages skip, in-progress uploads resume from last completed chunk.

#### Processing Sub-Stages

1. **process_game_lines** — Match `mlb_raw_game_lines` to `mlb_game_schedule` by (home, away, date)
2. **process_player_props_games** — Match props to games with ±1 day fuzzy date window
3. **process_player_props_players** — Manual mappings → exact normalized → fuzzy matching with suggestions
4. **process_player_props_teams** — Resolve team_id from (player_id, game_id) via boxscore UNION

#### Upload Retry/Backoff

Same pattern as existing backfill mode: 20 retries, linear backoff capped at 60s, `engine.dispose()` on connection errors. Survives laptop sleep/wake cycles.

## Key Design Decisions

### Why a Separate Local Linker (Not Extending mlb_linker.py)?

The existing `mlb_linker.py` works well for daily incremental use — it queries unlinked rows, processes in memory, updates inline. The local linker serves a different purpose: bulk offline processing with manual inspection between stages. Keeping them separate follows the NBA pattern and avoids complicating the daily codepath.

### Why Checkpoint JSON (Not DB-Based Tracking)?

The checkpoint lives alongside the CSV data in `mlb_linker_data/`. This is intentional:
- The whole point is offline processing — if the DB is unreachable, you still know your progress
- `_checkpoint.json` is human-readable for debugging
- Git-ignored by existing `*.json` rules

### Why Reuse Functions from mlb_linker.py?

The matching logic (normalize, fuzzy, game lookup) is identical between online and offline modes. Importing directly from `mlb_linker.py` avoids drift and keeps both modes in sync when matching logic changes.

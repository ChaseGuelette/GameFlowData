# Development Session 79 -- 2026-03-21

## Summary

Production security hardening session. Enabled Row Level Security on all 20 unprotected tables, added security headers, error boundaries, auth on the slate API route, narrowed `SELECT *` queries to explicit columns, and created a SCALING.md with bottleneck analysis and capacity roadmap.

## What Was Done

### 1. RLS Lockdown (Migration 018)

**File:** `database/migrations/018_rls_lockdown.sql`

Enabled RLS on 20 tables that previously had no row-level security:
- 3 DFS paper trading tables: `dfs_paper_daily_log`, `dfs_paper_entries`, `dfs_paper_legs`
- 1 operational table: `job_executions`
- 1 injury table: `rapidapi_injuries`
- 15 MLB tables (future use): `mlb_daily_predictions`, `mlb_daily_prediction_samples`, `mlb_game_schedule`, `mlb_paper_bets`, `mlb_paper_trading_daily_log`, `mlb_park_factors`, `mlb_player_game_statcast_batting`, `mlb_player_game_statcast_pitching`, `mlb_player_game_stats_batting`, `mlb_player_game_stats_pitching`, `mlb_player_season_advanced`, `mlb_players`, `mlb_raw_game_lines`, `mlb_raw_player_props`, `mlb_teams`

3 authenticated SELECT policies added for tables the dashboard reads:
- `auth_read_dfs_daily_log` on `dfs_paper_daily_log`
- `auth_read_dfs_entries` on `dfs_paper_entries`
- `auth_read_injuries` on `rapidapi_injuries`

All other tables default-deny. Python backend unaffected (uses `postgres` role which bypasses RLS).

**Verification:** Confirmed all 20 tables show `rowsecurity = true` in `pg_tables` and all 3 policies exist in `pg_policies` via Supabase SQL queries.

### 2. Security Headers

**File:** `dashboard/next.config.ts`

Added `headers()` async function applying to all routes:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`

CSP intentionally not added yet (requires tuning for Supabase, NBA CDN, and inline styles).

### 3. Error Boundaries

**Files:**
- `dashboard/src/app/(protected)/error.tsx`
- `dashboard/src/app/(public)/error.tsx`
- `dashboard/src/app/(auth)/error.tsx`

Each catches runtime errors in its route group and shows "Something went wrong" with a "Try again" button. Prevents white-screen crashes.

## Security Audit Findings

Full audit also identified:
- **Root `.env` file** — contains secrets but is properly `.gitignore`d and not tracked in git (confirmed)
- **Rate limiting** — Supabase Auth rate-limits login/signup at their API level. Only custom route (`/api/slate`) now auth-gated. Edge rate limiting noted as future item.
- **No SQL injection risk** — all queries use Supabase ORM, no raw SQL
- **No XSS risk** — no `dangerouslySetInnerHTML`, `innerHTML`, or `eval()` usage
- **CORS** — Next.js defaults (same-origin only), appropriate for the app
- **Supabase client separation** — anon key only in client/server, no service role exposure

# Development Session 46 — 2026-02-24

## Summary

## Problem

The Railway pipeline had been broken since Feb 19 with two independent failures:

1. **Daily Stats job timeout:** `play_type_scraper.py` (Step 8) calls `stats.nba.com` which blocks datacenter IPs (both Railway and GitHub Actions). The scraper hung indefinitely until the scheduler killed it at the 30-minute timeout. This also prevented paper bet resolution from running (process killed before reaching that step).

2. **Inference job crash:** `prediction_store.py` threw `TypeError: ufunc 'isfinite' not supported` at line 70. The `bl_confidence` column had mixed `None`/`float` values creating `object` dtype, which `np.isfinite()` can't handle.

**Key finding:** Steps 1-7 of `daily_stats_job.py` had been completing successfully — the CDN scraper confirmed only 3 games missing from the stats tables. The timeout happened during Step 8, killing the whole process.

## What Was Fixed

### Bug 1: `np.isfinite()` TypeError (`prediction_store.py`)

Added `pd.to_numeric(df[col], errors="coerce")` before the `np.isfinite()` call. This converts mixed `None`/`float` object-dtype columns to proper numeric dtype first. Non-numeric values become `NaN`, then the existing `.where()` replaces `NaN`/`inf` with `None` for PostgreSQL.

Also discovered and fixed a second bug in the same file: `pd.NaT` (Not a Time) timestamps in the `game_time` column were serialized as the string `'NaT'` to PostgreSQL instead of `NULL`. Added `v is pd.NaT` check in the row builder.

### Bug 2: Play Type Scraper Timeout (`daily_stats_job.py`)

Removed `play_type_scraper.py` from the pipeline entirely. `stats.nba.com` blocks datacenter IPs — the scraper works locally but not on Railway. Can be re-added when the API becomes accessible.

### Step Resilience (`daily_stats_job.py`)

Changed the step loop from 2-tuples to 3-tuples: `(command, description, critical)`. Critical steps (CDN scrape, linker, rolling averages, opponent allowed) abort on failure. Non-critical steps (team IDs backfill, position history, league averages) log a warning and continue. This ensures paper bet resolution always runs even when a non-critical step fails.

### Discord Step Counter (`scheduler.py`)

Fixed the step counter showing "1/7" on success. `re.search()` returned the first match ("Step 1/7") instead of the last. Switched to `re.findall()` and take `[-1]`. Also updated the hardcoded `Step (\d+)/8` regex to dynamic `Step (\d+)/(\d+)`.

### Auto Paper Bet Placement (`inference_job.py`)

After storing predictions, `inference_job.py` now automatically calls `PaperTrader.select_bets()` + `place_bets()`. This closes the paper trading loop — previously `place_bets.py` existed but was never called by any automated job. Non-fatal (failures don't affect predictions). `--skip-bets` flag available.

### DNP/0-minute Void Logic (`paper_trader.py`)

Added logic in `resolve_bets()` to void bets on players with `did_not_play=True` or `min=0`. Status set to `cancelled`, pnl to 0. Matches sportsbook behavior where DNP bets are refunded.

## Architecture Decisions

### Critical vs Non-Critical Steps

Rather than wrapping every step in try/except (which would silently swallow errors), the critical/non-critical distinction makes the intent explicit. Critical steps that affect prediction quality (data scraping, linking, rolling averages) still abort the pipeline. Non-critical steps (team ID backfill, position history, league averages) can fail without affecting today's predictions.

### Auto Bet Placement in inference_job (not scheduler)

Bet placement is in `inference_job.py` rather than as a separate scheduled job because:
1. It needs to run immediately after predictions are stored (not on a cron delay)
2. It's a natural extension of the inference pipeline (predict → store → bet)
3. The `--skip-bets` flag gives control without needing a separate scheduler entry
4. Non-fatal wrapper ensures prediction storage isn't affected by bet failures

### DNP Void by Minutes (not just `did_not_play` flag)

Some players have `did_not_play=False` but `min=0` (e.g., active roster but never entered the game). The void logic checks both conditions to match real sportsbook behavior.

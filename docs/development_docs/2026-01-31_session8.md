### 1. Calibration Fix: Conformal Recalibration (`quantile_trainer.py`)

**Problem:** THREES rate model Q0.10 had 35.2% coverage (target 10%) — a +25.2% gap during training. Combined THREES Q0.10 showed +20.4% gap on holdout. Root cause: zero-inflated distribution where 35%+ of `threes_per_min` is exactly 0. XGBoost's `quantileerror` objective assumes continuous targets and cannot learn the correct quantile when a massive point mass exists at 0.

**Fix:** Added conformal recalibration — a standard technique in probabilistic forecasting:
- After training each quantile, compute `delta = np.quantile(y_val - pred, q)` on validation data
- If coverage gap > `RECALIBRATION_GAP_THRESHOLD` (3%), store the offset
- At prediction time: `calibrated_pred = raw_pred + delta`
- Offsets persisted in model artifacts (`calibration_offsets` key in saved dict)

**Key code changes:**
- `QuantileModelSuite.RECALIBRATION_GAP_THRESHOLD = 0.03`
- `self.calibration_offsets: dict[float, float] = {}` in `__init__`
- Recalibration logic added after each quantile's training loop
- `predict_quantiles()` applies offset when non-zero
- `save()`/`load()` handle `calibration_offsets` key

### 2. Calibration Fix: Zero-Snap Handling (`monte_carlo.py`)

**Problem:** Continuous inverse CDF interpolation in MC sampling produced tiny positive values (e.g., 0.0001 threes/min) where the true value should be exactly 0. This inflated the lower quantiles of the combined (minutes × rate) distribution.

**Fix:** Added zero-snap logic in `_build_extended_quantile_fn()`:
```python
ZERO_SNAP_THRESHOLD = 1e-3
extended_values = np.where(extended_values < ZERO_SNAP_THRESHOLD, 0.0, extended_values)
```

Also refactored `_inverse_transform_sample()` to delegate to `_build_extended_quantile_fn()` instead of duplicating the extension logic.

### 3. Calibration Fix: Dynamic Combined Eval (`train_pipeline.py`)

eval_stats = [s for s in ["pts", "reb", "ast", "threes"] if s in pipeline.rate_models]

### 4. BL Parameter Sweep Analysis

**Findings:** User ran 40-config sweep (tau × edge × kelly):
- **No-BL configs:** 600-873 bets, +3% ROI. REB is +7.9% ROI (strongest stat).
- **All BL configs:** 0-12 bets across all tau values (0.01-0.30).

**Root cause analysis:** The BL confidence formula `confidence = 1 - exp(-0.5 * z²)` produces near-zero values for realistic betting edges:
- For P(over)=0.55 (a profitable 3% edge): z ≈ 0.13, confidence ≈ 0.008
- Combined with tau: `w = tau × confidence ≈ 0.0008`
- Edge after BL: `0.0008 × 0.03 = 0.000024` (0.002%)

The formula requires z > 1.0 for meaningful weight, but well-calibrated MC distributions produce z < 0.5 for genuine edges. This is a design flaw, not a model quality issue.

## Design Decisions

1. **Conformal recalibration over isotonic recalibration:** Originally planned isotonic (monotone) recalibration, but conformal is simpler and more robust for our use case. It's a single additive offset per quantile, doesn't require fitting a secondary model, and has theoretical guarantees from conformal prediction literature. Isotonic would be appropriate if the miscalibration were non-uniform across the feature space.

2. **Zero-snap threshold of 1e-3:** Chosen to be small enough that only true zero-mass values are affected, not legitimate small positive rates. A player averaging 0.01 threes/min (0.3 per 30 mins) would not be snapped to 0. Only values arising from interpolation artifacts in the zero-mass region are caught.

3. **3% recalibration gap threshold:** Below this, the offset is set to 0.0 (no adjustment). This prevents micro-adjustments on well-calibrated quantiles and keeps the model's natural predictions when they're within acceptable tolerance.

4. **No BL fix this session:** The BL confidence function needs redesign, but the user chose to do documentation first. The no-BL path is viable for paper trading in the interim.

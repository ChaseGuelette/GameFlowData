## Design Decisions

### 1. Pre-computed in DB vs. Computed at Query Time

All B2/B3/B4 features are pre-computed in `player_average_game_stats` via the backfill script, then pulled into the feature store via the existing `p_avg` LATERAL JOIN. This keeps the SQL simple (just `SELECT` more columns from the same join) and avoids complex window functions in feature store queries.

### 2. Momentum Ratio Denominators

PTS uses L3/L15 ratio; REB/AST/THREES use L3/L5 (since L15 isn't available for those stats in the LATERAL). The feature names all say `_l3_l15_ratio` for consistency — the model treats them as opaque feature names.

### 3. Starter Proxy

`player_games_started_l5` uses `minutes >= 20` as a starter proxy since `player_game_stats` has no `start_position` column. Defined as `STARTER_MINUTES_THRESHOLD = 20` constant.

### 4. Dead Code Cleanup

Deleted `_get_travel_and_rest_features()`, `_get_travel_features_single()`, `TEAM_LOCATIONS`, and `_haversine()` from the feature store. Rest features are now pre-computed in the DB (much cleaner). Travel distance was never in any feature list — it was dead code.

# Development Session 51 — 2026-02-28

## Summary

Rewrote the Railway scheduler from hardcoded hourly/half-hourly job definitions to 10-minute APScheduler cron cadence (11 AM – 11 PM ET). Fixed paper bet resolution gap that was making model P&L misleading. Added live game filtering to prevent false edges from mid-game line comparisons.

## Problem

Three related issues:

1. **Low-frequency scraping missed line movements.** The old schedule ran props-only scrapes 8 times/day (hourly 1-3 PM, half-hourly 4:30-6:30 PM). Lines move frequently; 10-minute cadence captures movements much better.

2. **Paper bets from later scrapes were never resolved.** Bets placed after the old 6:30 PM cutoff had no resolution path — only the daily stats job at 9 AM resolved bets, but it only checked dates with `team_game_stats`. The gap meant $389.46 in P&L was unreported.

3. **Live game false edges.** As scraping frequency increased, props for in-progress games were being compared against pre-game MC samples. This created false edges (e.g., a player already at 20 points with an over 24.5 line would appear as a strong over bet because the model's pre-game prediction assumed 0 points played).

## What Was Built

### 1. Scheduler Rewrite (`scheduler.py`)

Replaced 21 hardcoded job definitions with 7:

| Job | Schedule (ET) | Discord |
|-----|---------------|---------|
| Daily Stats | 9:00 AM | Always |
| Props Only | Every 10 min, 11 AM – 11 PM | Failures only |
| Edge Refresh | Every 10 min (+2 min), 11 AM – 11 PM | Failures only |
| Full Lines | 12:00 PM, 4:00 PM | Always |
| Inference | 12:15 PM, 4:15 PM | Always |

Key implementation: Added `silent_on_success` parameter to `run_job()`. High-frequency jobs skip Discord alerts on success but always alert on failure. Uses APScheduler `CronTrigger(hour='16-23,0-4', minute='*/10')` for the 11AM-11PM ET window.

### 2. Continuous Bet Resolution (`edge_refresh_job.py`)

Edge refresh step 7b now:
1. Calls `resolve_all_pending(exclude_today=True)` — resolves previous-day bets every 10 minutes
2. Places/updates paper bets for today

The `exclude_today` parameter filters `game_date < today` to prevent same-day false resolution. Two-layer safety: (1) date guard, (2) `team_game_stats` availability check in `resolve_bets()`.

### 3. Live Game Filter (`paper_trader.py`)

New `_get_started_game_ids()` method:
- Queries `raw_player_props_combined` for games where `commence_time < now()`
- Returns both padded and unpadded game_id formats for matching
- `select_bets()` skips any game in this set

### 4. Diagnostic Tool (`audit_and_resolve.py`)

Script for inspecting and fixing paper bet state:
- `--audit`: Shows bet counts by date/status, identifies resolvable pending bets and missed bet gaps
- `--resolve`: Resolves all pending bets where `team_game_stats` exist
- `--backfill --days N`: Re-places bets from historical predictions that were missed
- `--dry-run`: Preview mode

### 5. Historical Backfill Results

Before backfill: 81 resolved bets, $1,841.68 P&L
After backfill: 99 resolved bets, $2,231.14 P&L (+$389.46)
14 missed bets placed across 5 dates, 18 resolved

16 live-game bets from today identified and deleted.

## Technical Decisions

1. **`exclude_today=True` default** — Safer default prevents edge case where `team_game_stats` exists for a partially-completed game (e.g., after first game of a doubleheader). Can be overridden with `exclude_today=False` for manual resolution.

2. **`commence_time` from `raw_player_props_combined`** — Chose this table because it's always populated by props scrapes (the same pipeline that feeds edge refresh). Other tables (`raw_game_lines_staging`, `raw_game_lines_live`) might not have today's data.

3. **Silent Discord alerts** — 78 props + 78 edge refresh runs/day would spam the alerts channel. Only failures are interesting at this frequency.

4. **UPSERT idempotency** — Paper bets use `ON CONFLICT (game_date, player_id, stat_type, bet_direction) DO UPDATE WHERE status = 'pending'`. Line moves update the existing bet rather than creating duplicates.

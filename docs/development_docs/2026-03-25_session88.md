# Development Session 88 -- 2026-03-25

## Summary

Three improvements: (1) Fixed MLB dashboard page showing NBA games when no MLB predictions exist, (2) significantly enriched the AI Q&A chat with 5 new data sources (opponent matchup history, opponent injuries, game context, pace, minutes/usage details), and (3) persisted 11 model features to `daily_predictions` that were previously computed at inference but discarded (spread, total, home/away, starter probability, usage rate, pace, defensive rating, minutes floor/variance).

## What Was Done

### 1. MLB Games Fallback Fix

**Files:** `dashboard/src/app/(protected)/dashboard/page.tsx`, `dashboard/src/app/api/games/route.ts`

**Problem:** When MLB was selected in the sport switcher and no predictions existed, `fetchFallbackGames` called `/api/games` which was hardcoded to fetch the NBA CDN schedule. NBA games appeared on the MLB page.

**Fix:**
- `fetchFallbackGames` now passes `&sport=${sport}` and includes `sport` in its dependency array
- `/api/games` route accepts a `sport` query param (`nba` default, `mlb`)
- MLB schedule fetched from `statsapi.mlb.com/api/v1/schedule?sportId=1&date=YYYY-MM-DD&gameType=R`
- Cancelled/postponed MLB games filtered out (`D`, `DR`, `CR` status codes)

### 2. AI Q&A Data Enrichment

**File:** `dashboard/src/app/api/ask/route.ts`

Added 5 new data enrichment queries to the `/api/ask` route:

**New parallel query — Opponent-specific matchup history:**
- Fetches up to 5 games this player has played vs the current opponent this season
- Uses `matchup.ilike` filter for "vs. OPP" or "@ OPP" patterns
- Displayed as "MATCHUP HISTORY vs [OPP]" section in prompt

**New sequential queries — Opponent injuries:**
- Fetches Out/Questionable players from opposing team via `rapidapi_injuries`
- Enriched with position from `players` table and L15 averages from `player_average_game_stats`
- Same enrichment pattern as existing teammate injuries
- Displayed as "OPPONENT INJURIES ([OPP])" section

**New prompt section — Game Context (from model features):**
- Home/away with clear label
- Vegas spread with favored/underdog interpretation
- Vegas total
- Team + opponent pace with expected pace calculation (Dean Oliver formula)
- Opponent defensive rating with league average context

**Enhanced prompt section — Minutes/Usage Context:**
- Starter probability (percentage)
- Usage rate L5 (with league average ~20% context)
- Minutes avg L3 (short-window trend)
- Minutes floor L5 (worst recent game)
- Minutes std dev L5 (with stability interpretation: stable <3, moderate 3-7, high >7)
- Rest days, back-to-back flag, games in last 7 days

**Expanded opponent defense section:**
- Now shows L5/L15/SZN windows (was L5/L15 only)
- Per-100-possession rates alongside raw stats
- Offensive rating allowed
- Cross-stat context: always shows pts/reb/ast/threes even when analyzing a single stat

**Updated LLM rules:**
- Added instructions for game script/pace questions
- Added instructions for matchup history references
- Added instructions for opponent defense + injury cross-referencing

### 3. Feature Persistence to daily_predictions

**Files:** `src/models/prediction_store.py`, `src/models/daily_runner.py`

**Problem:** The XGBoost model uses features like `line_spread`, `line_total`, `is_home`, `player_starter_prob`, `player_avg_usg_pct_l5`, pace, and defensive rating during inference, but these values were never persisted to `daily_predictions`. They were computed, used for prediction, then discarded. The AI Q&A route couldn't access them.

**Fix — 11 new `feat_*` columns:**
| Column | Source Feature | Description |
|--------|---------------|-------------|
| `feat_line_spread` | `line_spread` | Vegas spread (negative = favored) |
| `feat_line_total` | `line_total` | Vegas over/under total |
| `feat_is_home` | `is_home` | Home (true) or away (false) |
| `feat_player_starter_prob` | `player_starter_prob` | Games started L5 / 5 (0-1) |
| `feat_player_avg_usg_pct_l5` | `player_avg_usg_pct_l5` | Usage rate L5 |
| `feat_team_avg_pace_l5` | `team_avg_pace_l5` | Team pace L5 |
| `feat_opp_avg_pace_l5` | `opp_avg_pace_l5` | Opponent pace L5 |
| `feat_opp_avg_def_rtg_l5` | `opp_avg_def_rtg_l5` | Opponent defensive rating L5 |
| `feat_player_avg_min_l3` | `player_avg_min_l3` | Minutes average L3 |
| `feat_player_min_floor_l5` | `player_min_floor_l5` | Minimum minutes in L5 |
| `feat_player_min_std_l5` | `player_min_std_l5` | Minutes standard deviation L5 |

- Added to `PREDICTION_COLS` in `prediction_store.py`
- Mapped in `_map_features_to_predictions()` in `daily_runner.py`
- Database migration applied: `ALTER TABLE daily_predictions ADD COLUMN IF NOT EXISTS ...` for all 11 columns
- Will populate starting with next inference run

## Key Design Decisions

1. **Context dump over DB querying** — Chose to pre-load all data into the system prompt rather than giving the LLM live database query tools. Simpler, faster (~1-2s vs 5-15s), cheaper (1 API call vs 3+), no SQL injection surface, and the use case is bounded (specific player prop analysis, not open-ended exploration).

2. **Feature persistence over re-derivation** — Chose to persist features to `daily_predictions` (option 1) rather than re-querying feature store tables in the ask route (option 2). Cleaner — features are computed once at inference time and available to all downstream consumers.

3. **Opponent matchup via matchup column** — Used `matchup.ilike` filter on `player_game_stats` rather than a complex join through `team_game_stats`. Simple, reliable for NBA 3-letter codes.

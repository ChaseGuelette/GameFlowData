# Development Session 54 — 2026-03-01

## Summary

Fixed critical DFS pipeline bugs (edge refresh early exit, RPC prediction dependency), added LIVE tags to game cards, built DFS performance tab, and made DFS/market data available before model inference runs.

## What Was Fixed

### 1. Edge Refresh Early Exit Blocking DFS (`edge_refresh_job.py`)

**Problem:** `sys.exit(0)` at line 496-501 fires when no MC samples exist (before inference runs daily). This killed the process before step 7c (DFS paper trading) could execute. DFS entries were never being built or resolved.

**Fix:** Moved DFS paper trading block from step 7c to **step 0** — runs immediately after engine creation, before the MC sample existence check. DFS paper trading uses market edge (devigged sportsbook consensus), not model predictions, so it doesn't need MC samples.

### 2. RPCs Dependent on `daily_predictions` (`004_fix_rpc_prediction_dependency.sql`)

**Problem:** Both `get_dfs_lines` and `get_sportsbook_lines` RPC functions joined on `daily_predictions` to scope which games to return lines for. Before inference runs, `daily_predictions` is empty → RPCs return nothing → DFS page and DFS paper trader have no data.

**Fix:** Updated both RPCs to scope by `commence_time::date = target_date` instead of joining `daily_predictions`. `get_dfs_lines` also now:
- LEFT JOINs `players` table for `player_name`
- Returns `game_time` (commence_time) in results
- Required DROP + recreate (return type changed)

**Verification:** 2,098 DFS lines and 5,490 sportsbook lines returned for today before inference.

### 3. DFS Page Blank in Market Mode (`dfs/page.tsx`)

**Problem:** `marketComparisons` useMemo had `if (!pred) continue` gate — when no predictions exist, no comparisons were built even though DFS lines and sportsbook lines were available.

**Fix:** Now constructs `DfsComparison` from DFS line data as fallback (player_name, game_time, player_id from RPC results). Model-dependent fields (q10-q90, model_prob) default to 0.

### 4. Stale Prediction Lines (Danny Wolf Investigation)

**Problem:** Danny Wolf's card showed Under 12.5 pts but line shopping only showed 10.5. Prediction stored `line=13.5` from bovada at inference time, while all sportsbooks had moved to 10.5.

**Root cause:** Edge refresh properly re-evaluates MC samples at new lines (`(samples > line).mean()`), selects sharpest book, recalculates BL blending, and UPSERTs updated predictions. But it wasn't running due to the sys.exit(0) bug above.

**Resolution:** The edge_refresh_job.py fix resolves this. Once deployed, edges update within 10 minutes of line movement.

## Technical Decisions

1. **Step 0 placement** — DFS paper trading at step 0 instead of step 7c ensures it runs even when edge refresh exits early. It's a market-only system (no model dependency), so ordering before inference-dependent steps is correct.

2. **`commence_time::date` scoping** — More direct than joining through `daily_predictions`. The `commence_time` column exists on every scraped line, making it the natural game-date scope.

3. **Client-side game_time backfill** — Not all predictions have game_time populated (570/783 missing). Rather than adding a DB migration, propagate from same-game predictions that have it. Simple, effective, no backend changes needed.

4. **"TBD" instead of blank** — `formatGameTime()` now always returns a visible string. Better UX than empty space.

# Session 17: Windows Task Scheduler Fixes & Incremental Stats

**Date:** 2026-02-09

## Summary

Fixed multiple critical bugs preventing Windows scheduled tasks from working correctly. Created a lightweight incremental version of the rolling average calculation, achieving a 1700x speedup for daily cron jobs.

## Problems Fixed

### 1. Virtual Environment Path Mismatch

**Problem:** Batch scripts referenced `.venv\Scripts\activate` but the actual path was `venv\Scripts\activate` (no leading dot).

**Impact:** All scheduled tasks failed immediately on venv activation.

**Fix:** Changed `.venv` to `venv` in all 3 batch scripts.

### 2. PYTHONPATH Missing

**Problem:** When `daily_stats_job.py` spawned subprocess calls like `python src/processing/backfill_team_ids.py`, the child process couldn't find the `src` module.

**Error:**
```
ModuleNotFoundError: No module named 'src'
```

**Impact:** Jobs failed at the first subprocess step that used `from src.db.client import get_engine`.

**Fix:** Added `set PYTHONPATH=C:\Users\Chase\Projects\GameFlowData` to all batch scripts before running Python.

### 3. Log File Permission Conflict

**Problem:** Batch scripts had shell redirect `>> logs\*.log 2>&1` but Python's `logging.FileHandler` was also trying to open the same file. On Windows, this caused a `PermissionError: [Errno 13]`.

**Impact:** Random job failures with permission denied on log files.

**Fix:** Removed shell redirect from batch scripts since Python handles its own logging.

### 4. SQL Syntax Error in Player Position History

**Problem:** The query used `:snap_date::DATE` which SQLAlchemy interpreted the first `:snap_date` as a parameter but then choked on `::DATE` (PostgreSQL cast syntax).

**Error:**
```
UndefinedColumn: column "snap_date" does not exist
```

**Impact:** `update_player_position_history.py` failed every time.

**Fix:** Changed `:snap_date::DATE` to `CAST(:snap_date AS DATE)` in two places.

## Performance Optimization

### Incremental Rolling Average Calculation

**Problem:** `populate_average_stats.py` recalculates rolling averages for ALL players (~4000) from full history. This took ~28 minutes — too slow for daily cron jobs.

**Solution:** Created `populate_average_stats_incremental.py` with these optimizations:

1. **Target only active players** — Only processes players who played on the target date
2. **Limited lookback** — Fetches last 20 games per player (enough for L15 window)
3. **UPSERT instead of TRUNCATE** — Updates existing rows instead of rebuilding entire table

**Results:**
| Metric | Full Script | Incremental |
|--------|-------------|-------------|
| Runtime | 1709 seconds (28.5 min) | 1.0 second |
| Players processed | ~4000 | ~150-300 per day |
| Games fetched | Full history | Last 20 per player |

**Speedup: 1700x**

## Batch Script Template

Final working batch script format:

```batch
@echo off
cd /d C:\Users\Chase\Projects\GameFlowData
set PYTHONPATH=C:\Users\Chase\Projects\GameFlowData
call venv\Scripts\activate
python src/orchestration/<job>.py
```

**Key points:**
- Use `venv` not `.venv`
- Set `PYTHONPATH` before running Python
- No shell redirect — Python handles logging
- `cd /d` handles drive letter changes

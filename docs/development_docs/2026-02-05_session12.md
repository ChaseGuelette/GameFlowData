### 1. Lightweight Incremental Linker

**Problem:** The existing linker (`nba_linker_local.py`) downloads the entire `raw_player_props_combined` table (25M+ rows) to CSV before processing. This is impractical for daily automated runs — downloading and re-uploading millions of rows every day is slow and unnecessary when most records are already linked.

**Solution:** Added new `incremental` command that:
- No CSV download — queries database directly
- Only processes unlinked records (`WHERE player_id IS NULL`)
- Loads reference tables once (teams, players, team_game_stats — all small)
- Updates directly via batched SQL

### 2. Team Name Normalization Fix

**Problem:** Odds API uses full team names ("Atlanta Hawks") while NBA API/team_game_stats uses abbreviations ("ATL"). The incremental linker was matching 0 games because team names didn't align.

**Solution:** Expanded `TEAM_NAME_ALIASES` to normalize all team names to 3-letter abbreviations:

```python
TEAM_NAME_ALIASES = {
    "Atlanta Hawks": "ATL",
    "Boston Celtics": "BOS",
    "Brooklyn Nets": "BKN",
    # ... 30 total teams
    "LA Lakers": "LAL",  # Variations also mapped
    "NOH": "NOP",        # Historical abbreviations
}
```

# Development Session 77 -- 2026-03-18

## Summary

Added bet context snapshot and user confidence rating to the betting flow. When a user takes a bet (via AnalysisModal or PropCard toggle), the full analysis context (quantiles, features, insights, probabilities, Kelly sizing, sportsbook lines) is now saved alongside the bet. The AnalysisModal also includes a 1-5 star confidence rating. On the history page, bets with saved context are expandable to review WHY a bet was taken.

```typescript
interface BetContext {
  quantiles: { q10, q25, q50, q75, q90 }
  l5_avg?: number | null
  season_avg?: number | null

  sportsbook_lines?: Array<{ bookmaker, line, over_odds, under_odds }> | null

```

Extended `PaperBet` with `bet_context?: BetContext | null` and `user_confidence?: number | null`.
Extended `TakeBetData` with `betContext?: BetContext` and `userConfidence?: number | null`.

### 3. Context Builder Helper

**File:** `dashboard/src/lib/buildBetContext.ts` (NEW)

Pure function `buildBetContext(prediction, options)` that:
- Extracts all `feat_*` columns (17 feature keys) into a features map
- Calls `generateInsights(prediction)` from `@/lib/insights`
- Determines bet direction and computes probabilities
- Accepts optional enrichment: `l5Avg`, `kelly`, `sportsbookLines`, `source`
- Returns a complete `BetContext` object

Used by both AnalysisModal (full context with Kelly/lines) and PropCard toggle (basic context).

## Key Design Decisions

1. **JSONB for context** — Flexible single column (~1-2KB per bet). Avoids 20+ narrow columns. Easy to evolve without migrations.
2. **Dedicated `user_confidence` column** — Extracted from JSONB for queryability. Enables future analytics like "my 5-star bets win at X%".
3. **Both bet paths save context** — PropCard toggle gets basic context (quantiles + features + insights). AnalysisModal gets full context (+ Kelly + sportsbook lines + confidence).
4. **Upsert overwrite is correct** — If a user quick-toggles then re-takes via AnalysisModal, the richer context overwrites the basic one.
5. **Progressive retry fallback** — Graceful degradation if migrations 013 or 017 aren't applied yet.

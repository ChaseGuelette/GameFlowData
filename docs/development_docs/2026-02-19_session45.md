# Development Session 45 — 2026-02-19

## Summary

Implemented frequent line scraping + edge refresh pipeline. Lines are now scraped using the live Odds API endpoint (not historical snapshots) on an aggressive intra-day schedule. A new lightweight `edge_refresh_job.py` recalculates edges from stored MC samples + fresh lines without re-running full inference. The scheduler expanded from 5 jobs to 21 jobs.

## Problem

Previously, lines were scraped 3x/day (12, 4, 6 PM ET) using the **historical** Odds API endpoint with hardcoded snapshots (17:00/23:00 UTC), and inference ran once at 6:30 PM. This meant:
- Predictions were based on stale lines (scraped hours earlier)
- Users received edges late in the day
- Line movement between scrapes was invisible

The historical API returns fixed snapshots — calling it at 1 PM still returns the 12 PM snapshot. Frequent scraping requires the **live** endpoint.

## Architecture Decisions

### Live vs Historical API

The `daily_player_props_scraper.py` already had `run_live_scrape()`, but it wrote to `raw_player_props_live`. Inference reads from `raw_player_props_combined`. Both tables share the same schema via the same `parse_and_store()` method, so adding `--target-table` was the cleanest approach — no schema changes, no new tables.

### Edge Refresh as Separate Job (not inline)

The edge refresh is a standalone job rather than being inline in `lines_job.py` because:
1. It needs a 2-minute offset to let the linker finish before fetching fresh lines
2. It has its own logging, Discord alerts, and error handling
3. It's independently testable and can be run manually
4. It avoids coupling the lightweight scraper with the heavier DB operations

### Self-Contained Edge Calculation

`edge_refresh_job.py` copies the lines query and edge math inline rather than importing from `daily_runner.py`. This avoids loading the entire model pipeline (XGBoost, feature store, MC predictor) just to recalculate edges. The math is pure SQL/pandas/numpy with no model dependencies.

### Two Inference Windows

Running inference at 12:15 PM and 4:15 PM (instead of once at 6:30 PM) ensures:
1. Users see predictions by 12:30 PM when sportsbooks post props (~12 PM ET)
2. The 4:15 PM run catches new player props added after noon (injury decisions, lineup changes)
3. Edge refreshes between windows keep edges current as lines move

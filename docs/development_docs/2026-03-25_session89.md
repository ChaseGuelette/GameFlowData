# Development Session 89 -- 2026-03-25

## Summary

Identified and fixed model weaknesses in under-bet recommendations for variable-minutes bench players. Root cause analysis of Collin Sexton (Under 14.5 PTS, L5 avg ~18) and Bones Hyland (Under 14.5 PTS, L5 avg 16.6) cases revealed: (1) the Q50 sanity check had a None-handling bug causing it to silently skip, (2) no check existed for when the player is literally averaging above the line, and (3) injury features are role-agnostic — the model couldn't distinguish "competing starter at your position is out" from "bench depth player is out." Built 3 improvements: improved sanity checks, dashboard warnings, and position-matched injury features.

## What Was Done

### 1. Root Cause Analysis

Investigated why the model recommended unders on players clearly trending over:
- **Sexton**: Q50=6.8, line=14.5, L5 avg ~18. Scored 25, 28, 30 in 3 of last 5. Multiple competing guards (Ivey, Simons) were out.
- **Hyland**: Q50=7.1, line=14.5, L5 avg=16.6. Over in 4 of last 5. Anthony Edwards out.

**Root causes identified:**
1. Q50 sanity check guard `if feat_l5 and pred_q50` — Python truthiness skips None/0 silently
2. No check for "L5 average is above the line"
3. Injury features (`team_out_count`, `team_out_min_sum`, etc.) are team-level aggregates with zero position/role specificity

### 2. Improved Sanity Checks

**Files:** `src/paper_trading/paper_trader.py`, `src/models/daily_runner.py`

Two checks now run on under bets/recommendations:
- **Q50 Divergence** (existing, fixed): `pd.notna()` instead of truthiness to handle None properly
- **L5 Above Line** (new): Rejects when L5 avg >= prop line. `L5_ABOVE_LINE_MARGIN = 0.0`

Both checks applied in paper_trader (bet selection) and daily_runner (BL recommendation flagging).

### 3. Sanity Flag Persisted to DB

**Files:** `src/models/daily_runner.py`, `src/models/prediction_store.py`

- New `sanity_flag TEXT` column on `daily_predictions`
- Set on ALL under-leaning predictions (not just recommended)
- Format: `"q50_divergence:62%|l5_above_line:18.0>14.5"` — pipe-separated
- Computed after BL blending loop in `_compute_bl_recommendations()`

### 4. Dashboard Warnings

**Files:** `dashboard/src/components/predictions/PropCard.tsx`, `dashboard/src/lib/insights.ts`, `dashboard/src/types/predictions.ts`

- PropCard: Amber warning banner below stat/line for flagged under predictions
- Insights: `'warning'` category added to Insight type. Sanity flag warnings `unshift`ed to top of insights list
- Position injury insight: "same-position starter out — major opportunity" when `starter_sum >= 0.8`

### 5. Position-Matched Injury Features (4 new)

**Files:** `src/models/feature_store.py`

| Feature | Signal |
|---------|--------|
| `team_out_same_pos_count` | # of OUT teammates in same G/W/B group |
| `team_out_same_pos_min_sum` | Combined L5 avg minutes of those players |
| `team_out_same_pos_usg_sum` | Combined L5 usage% of those players |
| `team_out_same_pos_starter_sum` | Sum of `games_started_l5 / 5.0` — the key feature. 1.0 = starter out, 0.1 = bench depth |

**Bulk training path:**
- `_load_injury_features_bulk()` now joins `player_position_history` via LATERAL to get `inj_position_group`
- Also fetches `games_started_l5` for starter_prob computation
- `get_training_dataset()` groups by `(team_id, date, position_group)` to produce position-matched aggregates
- Merges on `(team_id, game_date, position_group)` into training DataFrame

**Inference path:**
- `_get_injury_context()` accepts `player_position_group` parameter
- Runs position-filtered SQL query joining `player_position_history` + `player_average_game_stats`
- Excludes the player themselves (`ri.player_id != :player_id`)

Added to all 5 feature lists (MINUTES, PTS, REB, AST, THREES).

### 6. Migration Applied

Migration 021 applied to Supabase via MCP: 5 ALTER TABLE statements adding `sanity_flag`, `feat_team_out_same_pos_count`, `feat_team_out_same_pos_min_sum`, `feat_team_out_same_pos_usg_sum`, `feat_team_out_same_pos_starter_sum`.

## Key Design Decisions

1. **G/W/B granularity is sufficient** — More granular positions (PG vs SG) would fragment the data. G/W/B maps to how NBA rotations work and is consistent with existing opponent defense features.

2. **`starter_sum` over `count`** — Raw count ("2 guards out") doesn't capture impact. `starter_sum` distinguishes "Ant Edwards is out" (1.0) from "two deep bench guards are out" (0.2 total).

3. **Sanity flag on ALL under predictions, not just recommended** — Dashboard should warn users even on predictions that aren't "Model Picks." Users browse all predictions.

4. **Force-include recommended for retrain** — Feature selector may not pick up these features without guidance since the signal is sparse (most games don't have same-position starters out). Force-include ensures the model sees them.

# Development Session 48 — 2026-02-25

## Summary

Implemented the DFS Edge Finder page (`/dfs`) — a new dashboard page that surfaces mispriced DFS props from PrizePicks, Underdog, Pick6, and Betr by comparing their lines against the model's true probability estimates.

## Problem

The model produces accurate probability distributions for player props, but this was only being used to evaluate traditional sportsbook lines. DFS platforms (PrizePicks, Underdog, Pick6, Betr) offer binary over/under picks with fixed payouts per slip type, and they often set different lines than sportsbooks. Users had no way to see where DFS platforms were mispricing props relative to model truth.

## What Was Built

### 1. Scraper Update (`daily_player_props_scraper.py`)

Added `us_dfs` to the Odds API `regions` parameter on both live and historical endpoints. DFS platforms now flow into `raw_player_props_combined` with the same schema as sportsbook lines. No other scraper changes needed — the existing `parse_and_store()` method handles any bookmaker.

### 2. Supabase RPC Function (`get_dfs_lines`)

Server-side function that efficiently queries the latest DFS line per bookmaker/player/stat for a given date's games. Uses `ROW_NUMBER()` partitioned by (player_id, game_id, bookmaker, market_key, outcome_label) ordered by `snapshot_time DESC`. Pivots Over/Under into a single row via conditional aggregation.

**Type fix:** Initial migration declared `player_id` as `integer`, but the actual column is `bigint`. Required `DROP FUNCTION` + recreate since PostgreSQL doesn't allow changing return types via `CREATE OR REPLACE`.

**Performance:** Required a partial index `idx_props_bookmaker_dfs` on `raw_player_props_combined` for DFS bookmakers. Without it, queries on the 26M+ row table timed out (>30s). With the index, the RPC returns 564 rows in <1s.

### 3. DFS Types (`types/dfs.ts`)

- `DfsLine` — Raw RPC result type
- `DfsComparison` — Joined prediction + DFS data per player/stat
- `DfsPlatformLine` — Per-platform computed data (line diff, re-estimated prob, EV)
- `DFS_SLIP_TYPES` — Break-even thresholds per slip type
- `DFS_PLATFORM_NAMES` — Display names
- `MARKET_TO_STAT` / `STAT_TO_MARKET` — Bidirectional mapping

### 4. Shared Utilities (`lib/dfs-utils.ts`)

Extracted `estimateUnderProb` from `AnalysisModal.tsx` into a shared module. Added `estimateOverProb`, `calcDfsEv`, and `calcAllSlipEvs`. Refactored `AnalysisModal` to import from this module instead of having its own copy.

### 5. DFS Components

**`DfsFilters.tsx`** — Control bar with platform filter tabs, slip type dropdown, stat filter tabs, and +EV toggle. Reuses the same tab styling pattern as `FilterTabs.tsx`.

**`DfsTable.tsx`** — Sortable table with 10 columns (Player, Stat, Platform, Sharp Line, DFS Line, Diff, Direction, Model %, Break-Even, Edge). Color-coded edge cells with three tiers. Uses existing `PlayerAvatar` and `Badge` components.

### 6. DFS Page (`/dfs`)

Full page implementation:
- Fetches predictions and DFS lines in parallel via `Promise.all`
- Joins client-side on `(player_id, game_id, stat↔market_key)` using Maps
- For each DFS line: calls `estimateOverProb()` at the DFS-specific line to get model probability
- Computes EV = model_prob - break_even for each slip type
- Flattens into table rows with filtering and sorting
- KPI summary cards: total +EV picks, average edge, best edge pick
- Date selector matching dashboard pattern

### 7. Navbar Update

Added "DFS" link between "Props" and "History" in the protected navigation bar.

## Architecture Decisions

### Client-Side Join (Not Server-Side)

Predictions are already fetched for the dashboard page with the same query. DFS lines come from the new RPC. Joining in the browser avoids adding a complex server-side function that duplicates edge calculation logic. The data volume is small (~500 DFS lines, ~200 predictions) so client-side join is instant.

### Quantile Interpolation at DFS Line

The key insight: DFS platforms set different lines than sportsbooks. PrizePicks might have a player at 25.5 points while the sharp line is 24.5. Using `model_prob_over` from `daily_predictions` (computed at the sharp line) would be wrong. We must re-estimate at the DFS line using the 5-point quantile interpolation.

### Shared estimateUnderProb

Extracting this to `dfs-utils.ts` eliminates code duplication between `AnalysisModal` (which uses it for per-line edge calculation in line shopping) and the DFS page (which uses it for per-platform-line probability estimation).

### Partial Index for Performance

A full table scan of 26M+ rows for 4 DFS bookmakers was timing out. The partial index filters to only DFS bookmaker rows at the index level, making the RPC function fast even at scale.

# Development Session 81 -- 2026-03-21

## Summary

Added combo market support (PRA, P+R, P+A, R+A) across the entire pipeline — from Monte Carlo sample derivation through production inference, backtesting, paper trading, line scraping, and the dashboard frontend. No new model training needed; combo predictions are derived by element-wise summing existing MC sample arrays (correlations preserved via Gaussian copula).

## What Was Done

### 1. Centralized Combo Config

**File:** `src/config/combo_config.py` (NEW)

Created single source of truth for combo market definitions:
- `COMBO_DEFINITIONS` — maps combo stat keys to component stats and sportsbook market keys
- `COMBO_STATS` — set of combo stat keys for quick membership checks
- `STAT_TO_MARKET` / `MARKET_TO_STAT` — bidirectional mappings including both base and combo stats
- Imported by: `monte_carlo.py`, `daily_runner.py`, `backtest_harness.py`, `edge_refresh_job.py`

### 2. Monte Carlo Combo Derivation

**File:** `src/models/monte_carlo.py`

Added `derive_combo_samples()` module-level function:
- Takes `samples_dict` (keyed by `(player_id, game_id, stat)`) and `predictions_list`
- For each unique (player_id, game_id), sums component stat sample arrays
- Returns `(combo_predictions_list, combo_samples_dict)`
- Combo samples are NOT stored to DB — always derived on-the-fly

### 3. Daily Runner Integration

**File:** `src/models/daily_runner.py`

## Key Design Decisions

1. **No new model training** — Combos are derived from existing per-stat MC samples. The Gaussian copula ensures correlations between PTS/REB/AST are preserved in the sum.

2. **No DB storage of combo samples** — Always derived on-the-fly from base samples. Saves storage (~80KB/player/day) and avoids consistency issues.

3. **Centralized config** — Single `combo_config.py` prevents duplicate definitions across 6+ files.

4. **`derive_combo_samples()` as module function** — Not a method on `MonteCarloPredictor` because it doesn't need predictor state; just operates on numpy arrays.

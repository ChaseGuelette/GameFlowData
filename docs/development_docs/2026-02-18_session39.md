# Development Session 39 — 2026-02-18

## Summary

Built the Data Vault page (`/stats`) — a dense, Monster.bet-style heatmap stat table for exploring player, team, and defense-vs-position rolling averages. All data comes from pre-computed tables already in the database; no new pipeline work needed.

## Context

The dashboard previously focused on predictions (PropCards, edges, Model Picks) but had no way for users to explore raw player and team stats in a dense, sortable format. The Supabase database already contains rich pre-computed rolling averages across `player_average_game_stats`, `player_average_advanced_stats`, `team_average_game_stats`, and `team_allowed_by_position` — this data just needed a frontend.

## Implementation

### Database (Supabase Migration)

Created 3 database views to provide pre-joined, latest-row-per-entity data:

| View | Rows | Source Tables |
|------|------|---------------|
| `player_stats_latest` | ~529 | game stats + advanced stats + players + position history |
| `team_stats_latest` | 30 | team game stats + teams |
| `defense_by_position_latest` | 90 | team allowed by position + teams (G/W/B only) |

All use `DISTINCT ON` with `ORDER BY game_date DESC` for efficient latest-row selection. Granted `SELECT` to both `authenticated` and `anon` roles.

### Frontend (8 New Files)

**Types & Column Definitions:**
- `dashboard/src/types/stats.ts` — TypeScript types: `ColumnDef`, `StatRow`, `SortState`, `WindowSuffix`, tab/category union types
- `dashboard/src/lib/stats/columns.ts` — All column definitions organized by tab/category. Uses `{window}` placeholder pattern in `dbColumn` (e.g., `avg_pts_{window}`) swapped at render time for `l5`/`l15`/`szn`

**UI Components:**
- `StatTabs` — Players / Teams / Defense vs Position main tab bar
- `CategoryTabs` — Generic sub-category pill tabs (Box Score, Shooting, etc.)
- `WindowToggle` — L5 / L15 / SZN rolling window toggle
- `PositionFilter` — All / Guards / Wings / Bigs position filter

**Core Component:**
- `HeatmapTable` — The main table with:
  - Percentile-based 5-step blue heatmap coloring (computed via `useMemo`)
  - `invertHeatmap` support for negative stats (TOV, DRtg, PF)
  - Sticky name column + optional position/team columns + sticky header
  - Click-to-sort column headers with arrow indicator
  - Value formatting (int, dec1, dec2, pct1, plusMinus1)

**Page:**
- `app/(protected)/stats/page.tsx` — Fetches all 3 views in parallel on mount, manages tab/filter/sort state per tab, client-side filtering for player search/team/position/minGP

**Navbar Modification:**
- Added "Data Vault" link to `/stats` in the nav bar

### Design Decisions

1. **Views over RPC functions:** Initially planned `RETURNS SETOF record` RPC functions, but Supabase's client works much cleaner with views (auto-typed, simple `.from('view').select('*')`)
2. **Client-side filtering:** With only ~529 player rows and 30 team rows, fetching all data once and filtering client-side is much simpler than parameterized server queries
3. **Column template pattern:** `{window}` placeholder in column definitions allows the same column definitions to work across L5/L15/SZN without duplication
4. **Per-tab state:** Each tab (Players/Teams/Defense) maintains its own sort state and window selection, so switching tabs preserves context

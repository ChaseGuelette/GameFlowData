### 2. APScheduler-Based Scheduler

Created `src/orchestration/scheduler.py` (~145 lines):

```python
from apscheduler.schedulers.blocking import BlockingScheduler
from apscheduler.triggers.cron import CronTrigger

def main():
    scheduler = BlockingScheduler(timezone="UTC")

    # Daily Stats - 9:00 AM ET = 14:00 UTC
    scheduler.add_job(
        run_daily_stats,
        CronTrigger(hour=14, minute=0),
        id="daily_stats",
        name="Daily Stats Job (9 AM ET)",
    )

    # Lines - 12:00 PM ET = 17:00 UTC
    scheduler.add_job(
        run_lines,
        CronTrigger(hour=17, minute=0),
        id="lines_noon",
        name="Lines Job - Noon (12 PM ET)",
    )

    # ... additional jobs ...

    scheduler.start()
```

**Benefits over Railway cron:**
- All jobs in single service (~$5/month)
- Better error handling with retries
- Graceful shutdown handling
- Single log stream

### 3. Production Model Workflow

**Problem:** 44+ training runs (each ~50MB) would pollute git repository.

**Solution:** Production folder pattern

**Created `scripts/promote_model.py`:**
```python
def promote_model(source_run: str | None = None):
    """Copy a training run to production folder."""
    artifacts_path = Path("src/models/artifacts")
    prod_path = artifacts_path / "production"

    # Find source run
    if source_run:
        source_path = artifacts_path / source_run
    else:
        # Auto-detect latest complete run
        runs = sorted([d for d in artifacts_path.iterdir()
                       if d.name.startswith("run_")
                       and not d.name.endswith("_incomplete")])
        source_path = runs[-1]

    # Copy to production
    shutil.copytree(source_path, prod_path, dirs_exist_ok=True)

    # Create source marker
    (prod_path / ".source").write_text(source_path.name)
```

## Deployment Issues Resolved

### Issue 1: Railway ran wrong start command

**Error:** Railway tried `python -m GameFlowData`

**Cause:** Auto-detected Python but guessed module name

**Fix:** Added explicit `startCommand` in `railway.toml`

### Issue 2: `pip: command not found`

**Error:** Nixpacks build failed finding pip

**Cause:** Custom `nixpacks.toml` with nix packages didn't set up pip correctly

**Fix:** Removed custom `nixpacks.toml`, let Railway auto-detect

### Issue 3: psycopg2 compilation failed

**Error:** `No module named pip` / missing libpq

**Cause:** psycopg2 needs PostgreSQL dev headers

**Fix:** Changed to `psycopg2-binary` (pre-compiled wheels)

### Issue 4: Wrong Windows task names

**Error:** `schtasks /change` failed with "task does not exist"

**Cause:** Tasks named `GameFlow-*` not `GameFlowData_*`

**Fix:** Queried existing tasks with `Select-String 'GameFlow'`

## Design Decisions

### APScheduler vs Railway Cron

**Chosen:** APScheduler in single service

**Rationale:**
- Railway cron requires separate service per job (~$5 each = $25/mo)
- APScheduler runs all jobs from one always-on worker (~$5/mo)
- Better error handling and retry logic
- Single log stream for all jobs

### Production Folder vs Docker Image

**Chosen:** Production folder committed to git

**Rationale:**
- Simpler than building model into Docker image
- Easy to update (just run promote_model.py)
- Git history shows model versions
- ~50MB acceptable for production artifacts

### UTC Scheduling

**Chosen:** UTC times in scheduler

**Rationale:**
- Railway runs in UTC
- No daylight saving time complexity
- Clear ET → UTC conversion documented

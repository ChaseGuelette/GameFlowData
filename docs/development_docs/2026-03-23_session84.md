# Development Session 84 -- 2026-03-23

## Summary

Implemented prop line drift detection and selective re-inference in the edge refresh job. `prop_line_*` features are the #1 most important features in the production XGBoost model, but they get baked into MC samples at inference time (12:15 PM / 4:15 PM ET). By game time (7-10 PM ET), lines may have moved 1-3+ points, causing the underlying MC distribution to be anchored to stale values. The fix detects when lines have drifted significantly and re-runs inference for only the affected players.

### 4. Edge Refresh Job — Major Enhancement

**File:** `src/orchestration/edge_refresh_job.py` (modified)

Added 4 new functions and integrated drift detection into the main flow:

#### `detect_stale_predictions(predictions_df, fresh_lines_df)`
- Guards against missing `prop_line` column (pre-migration data).
- Filters to base stats only (pts, reb, ast) with non-null `prop_line`.
- Renames fresh line column to `fresh_line` before merge to avoid suffix issues.
- Returns list of `(player_id, game_id, stat)` tuples where drift >= `DRIFT_THRESHOLD` (1.0 points).
- Logs each stale prediction with prop_line → fresh_line drift values.

#### `_get_cached_pipeline_and_predictor()`
- Lazy-loads `PlayerPropsModelPipeline` and `MonteCarloPredictor` once per process lifecycle.
- Cached at module level (`_cached_pipeline`, `_cached_predictor`).
- Looks for model in `production/` folder first, then latest `nba_run_*` directory.
- Passes `feature_store=None` (not needed during prediction).
- Loads copula params and calibration offsets from model artifacts.

#### `_get_home_team_ids(engine, target_date)`
- Queries `raw_game_lines_staging` for home team IDs on the target date.
- Returns `set[int]` for O(1) membership checks.
- Used to determine `is_home` parameter for `FeatureStore.get_player_game_features()`.

#### `reinfer_stale_players(stale_keys, samples_dict, predictions_df, engine, target_date, store)`
- Gets unique `(player_id, game_id)` pairs from stale keys.
- Determines `is_home` from home_teams set.
- Builds fresh features via `FeatureStore` using parallel `ThreadPoolExecutor` (8 workers).
- Runs batch prediction via cached `MonteCarloPredictor.predict_batch_for_date()`.
- Replaces stale entries in `samples_dict` with fresh samples.
- Updates quantile columns + `prop_line` in `predictions_df`.
- Re-derives combo samples via `derive_combo_samples()`.
- Persists updated samples to DB via `store.store_samples()`.
- Returns updated `(samples_dict, predictions_df)`.

#### Main Flow Integration
Inserted between "fetch fresh lines" (step 5) and "recalculate edges" (step 6):
```
5a. Detect prop_line drift
5b. If drift detected and not --skip-reinference: re-infer stale players
```

#### CLI Flag
- `--skip-reinference` disables drift detection and selective re-inference.

## Key Design Decisions

1. **Re-inference over approximation** — The model learned complex non-linear relationships between prop_line and quantile outputs. A linear shift would be an approximation; re-running inference gives the correct answer.

2. **Lazy pipeline loading** — Model pipeline (~2-3s to load) is cached at module level. First edge refresh cycle with drift pays the cost; subsequent cycles reuse the cached pipeline.

3. **1.0 point drift threshold** — Conservative threshold. A 1-point move on a 22.5 PTS line is ~4.4%, which meaningfully shifts probability estimates. Can be tuned up if re-inference triggers too often.

4. **Base stats only** — Drift detection only runs for pts/reb/ast (which have prop_line features). Combo stats are re-derived from updated base stat samples.

5. **prop_line vs line** — `prop_line` is the model feature value from inference time. `line` is the sharpest-book line used for edge calculation (overwritten each cycle). These are different values from different sources.

## Bugs Encountered & Fixed

1. **`KeyError: 'line_fresh'`** — Merge suffixes don't apply when column names don't overlap. Fixed by explicitly renaming `line` to `fresh_line` before merge.

2. **`KeyError: 'prop_line'`** — Legacy data from before migration doesn't have the column. Fixed by adding early return guard.

3. **`_get_home_team_map` return type** — Function returned `set[int]` but was annotated as `dict[str, int]`. Renamed to `_get_home_team_ids` with correct annotation.

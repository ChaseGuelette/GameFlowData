# Development Session 78 -- 2026-03-19

## Summary

Retrained all 4 models (minutes + pts/reb/ast rate) with `player_starter_prob` force-included, ran A/B backtest against production, and decided NOT to promote. The feature improves calibration and reduces drawdown but hurts ROI by 3.19pp and regresses AST by 6.24pp. This is the same pattern as calibration offsets — smoothing out "miscalibration" erodes the under-betting edge that generates profit.

## Key Findings

### player_starter_prob Hurts Edge-Finding
The feature makes the model "better calibrated" (lower drawdown, better hit rate) but reduces its ability to find profitable edges. This is exactly the same pattern as calibration offsets — the model's apparent miscalibration IS the betting edge. Smoothing it out removes the edge.

### 4th Confirmation That Offsets Hurt ROI
The initial challenger run with offsets (31.16% ROI) vs without offsets (41.59% ROI) provides a 4th independent confirmation that combined calibration offsets should never be deployed. The ~10pp penalty from offsets is consistent across all previous tests.

### Feature May Be Useful as Post-Model Filter
While `player_starter_prob` doesn't help as a model training feature, it could be valuable as a post-model decision filter:
- Only take bets on confirmed starters (starter_prob >= 0.7)
- Require higher edge threshold for non-starters
- Scale Kelly sizing by starter probability
- Sanity-check minutes predictions against starter status

This was identified as a future experiment direction.

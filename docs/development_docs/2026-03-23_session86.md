# Development Session 86 -- 2026-03-23

## Summary

Fixed severe PTS model degradation (-$15,203 PnL, 30% win rate last 7 days) while REB and AST remained healthy. Root cause: minutes x rate decomposition creating absurdly low Q50 predictions for variable-minutes players, generating fake under edges. Three-pronged fix: Q50 vs L5 sanity check, MIN_MINUTES threshold increase (5 -> 8), and model retrain with fresh data. Also fixed a type mismatch bug in the MLB batter training pipeline.

## What Was Done

### 1. Q50 vs L5 Sanity Check

**Files:** `src/paper_trading/paper_trader.py`, `src/models/daily_runner.py`

Added `MAX_Q50_DIVERGENCE = 0.30` constant to both files. When the model's Q50 prediction diverges more than 30% below the player's L5 average, under bets and under recommendations are rejected.

**Paper Trader (`paper_trader.py`):**
- Added `pred_q50` and `feat_player_avg_stat_l5` to the SELECT query from `daily_predictions`
- After direction selection (over/under) and before odds filtering, added divergence check
- Only applies to `direction == "under"` — over bets are unaffected
- Logs warning with player name, stat, Q50 value, L5 value, and divergence %

**Daily Runner (`daily_runner.py`):**
- Swapped steps 8 and 9 in `run_for_date()` so that `_map_features_to_predictions()` runs before `_compute_bl_recommendations()`. This ensures `feat_player_avg_stat_l5` is available when computing BL recommendations.
- In `_compute_bl_recommendations()`, before setting `is_recommended = True`, checks if the recommended direction is "under" and applies the same 30% divergence filter
- Uses a `skip` flag instead of `continue` to avoid skipping the `bl_computed` counter

**Data-driven justification:** Analysis of all 29 PTS bets showed higher-edge bets performed WORSE (fake edges from under-prediction). Applying the 30% sanity check in backtesting reduced PTS PnL from -$15,203 to -$386.

### 2. MIN_MINUTES_FOR_STATS Raised from 5 to 8

**Files:** `src/processing/populate_average_stats.py` (line 41), `src/processing/populate_average_stats_incremental.py` (line 58)

Games where the player played fewer than 8 minutes (was 5) are now excluded from rolling stat averages (L3, L5, L15, season). This prevents garbage-time cameos and early injury exits from distorting rolling averages. Schedule features (rest_days, games_last_7d) still count all games.

**Rationale:** "That way we can still take care of those games where the model correctly thinks they will play low minutes and we win because of it." The minutes model still sees all games — only the stat rate rolling averages filter low-minutes appearances.

## Key Decisions

1. **30% divergence threshold** — Chosen based on data analysis showing it catches the worst fake edges while preserving legitimate under predictions
2. **8-minute threshold** — Balances filtering garbage time (5-7 min appearances) while preserving legitimate low-minutes data that the minutes model needs
3. **Locked hyperparams** — No retuning. Last retrain confirmed production hyperparams are good; the issue was stale data, not model architecture
4. **No offsets deployed** — 5th confirmation that calibration offsets hurt ROI. Code is backward-compatible no-op when absent.

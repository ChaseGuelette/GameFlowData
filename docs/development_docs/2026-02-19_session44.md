## Architecture Decisions

### Client-Side Pivot (not a database view)
Play type data is stored in long format (one row per team per play type per grouping = 660 rows). Rather than creating a Supabase view to pivot this, we:
1. Fetch all 660 rows in the initial parallel `Promise.all` call
2. Use `pivotPlayTypes()` to transform to wide format client-side
3. Re-pivot via `useMemo` when the offense/defense toggle changes

This avoids a complex `crosstab()` SQL view and keeps the pivot logic transparent in TypeScript.

### Column Definitions Pattern
Play type columns use `windowless: true` since the data is season-level (no L5/L15/SZN windows). Column keys match the pivoted synthetic column names (e.g., `isolation_poss_pct`). The `rawPct1` format is used for frequency (DB stores 0.059, pivot multiplies by 100, format displays "5.9%").

### Heatmap Coloring
The existing `HeatmapTable` percentile computation works well — with 30 teams per column, it ranks teams and applies the 5-step blue gradient. No special handling needed for play types.

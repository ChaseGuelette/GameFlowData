**Date:** 2026-02-09

## Summary

## Problem 1: Truncated NegBin Mu Training Target

### Root Cause Investigation

Training log showed severe calibration failures for THREES count model (C4):
- Q0.10: 35.8% coverage (target 10%) — GAP +25.8%
- Q0.25: 46.2% coverage (target 25%) — GAP +21.2%
- Q0.50: 73.1% coverage (target 50%) — GAP +23.1%
- Q0.75: 91.7% coverage (target 75%) — GAP +16.7%
- Q0.90: 98.4% coverage (target 90%) — GAP +8.4%

Despite the zero classifier working well (75.6% accuracy), the count model was systematically over-predicting.

### Diagnosis

Created test scripts to compare actual vs model distributions:
- `scripts/test_threes_distribution.py` — Compares actual distribution vs NegBin
- `scripts/test_threes_global_params.py` — Tests calibration with correct vs wrong mu

**Key finding:** With correct MLE parameters (mu=1.657, alpha=0.297), model quantiles match actual:
```
Q0.10: actual=0, model=0
Q0.25: actual=0, model=0
Q0.50: actual=1, model=1
Q0.75: actual=2, model=2
Q0.90: actual=4, model=4
```

But XGBoost was predicting mu≈2.5 instead of μ≈1.66.

### The Bug

In `truncated_negbin.py` lines 188-190:
```python
# Target for mu model: log of sample value (proxy for conditional mean)
log_mu_target = np.log(y_np + 0.5)  # +0.5 for stability at y=1
```

This is **wrong** because:
- `y` values are from the **truncated** distribution (conditioned on X > 0)
- μ should be the mean of the **untruncated** distribution
- For truncated NegBin: E[X | X > 0] = μ / (1 - P(X=0))
- So observed values are inflated by factor 1/(1-p_zero) ≈ 1.35

### The Fix

Applied truncation adjustment factor using global MLE P(X=0):

```python
# Compute P(X=0) using global MLE params
n_global = 1.0 / self._global_alpha
p_global = n_global / (n_global + self._global_mu)
p_zero_global = nbinom.pmf(0, n_global, p_global)
truncation_factor = 1.0 - p_zero_global  # ~0.74

# Correct target: scale down by truncation factor
log_mu_target = np.log((y_np + 0.5) * truncation_factor)
```

This scales training targets down by ~26%, bringing predicted mu from ~2.5 to correct ~1.66.

## Problem 2: Training/Inference Race Condition

### The Issue

User asked: "If one is currently training when the cron job executes, will that cause issues?"

Analysis revealed:
1. Training creates `run_YYYYMMDD_HHMMSS` directory at the **START** of training
2. Inference job auto-selects the most recent `run_*` directory
3. If training is in progress, inference would pick the incomplete directory
4. Result: `FileNotFoundError` crash when model files don't exist

### The Fix

**Option A: Atomic rename pattern** (implemented)

1. **Training pipeline** (`train_pipeline.py`):
   - Creates directory as `run_YYYYMMDD_HHMMSS_incomplete`
   - Renamed to `run_YYYYMMDD_HHMMSS` only after all artifacts saved (step 8)

2. **Inference job** (`inference_job.py`):
   - Filters out `_incomplete` directories when auto-selecting
   - Improved error message if only incomplete runs exist

Result: If inference runs at 6:30 PM while training is in progress, it uses the previous completed model.

## Technical Notes

### Why Truncation Adjustment Works

For truncated NegBin with μ and α:
- P(X=0) = (1 + α×μ)^(-1/α)
- E[X | X > 0] = μ / (1 - P(X=0))

With μ=1.657, α=0.297:
- P(X=0) ≈ 0.26
- E[X | X > 0] = 1.657 / 0.74 ≈ 2.24

This matches the observed positive mean (~2.2), confirming the MLE parameters are correct.

### Why Global P(X=0) is Used

We use the global MLE P(X=0) for the truncation factor because:
1. It's already computed during training
2. Individual-level P(X=0) would require a circular dependency (need mu to compute p_zero, need p_zero to train mu)
3. The global factor provides sufficient correction for calibration purposes

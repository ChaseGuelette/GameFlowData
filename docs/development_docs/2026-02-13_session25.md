## Technical Details

### Health Check Architecture

```python
class DatabaseHealthChecker:
    def __init__(self, engine, days: int = 7, verbose: bool = False):
        self.engine = engine
        self.days = days
        self.verbose = verbose
        self.results: list[CheckResult] = []

    def run_all_checks(self) -> list[CheckResult]:
        self._check_data_freshness()
        self._check_game_data_completeness()
        self._check_prop_linking()
        self._check_aggregation_sync()
        self._check_injury_linking()
        self._check_position_history()
        self._check_prediction_coverage()
        self._check_foreign_keys()
        return self.results
```

### CheckResult Dataclass

```python
@dataclass
class CheckResult:
    check: str          # Check name (e.g., "data_freshness")
    status: str         # "passed", "warning", "failed"
    message: str        # Human-readable summary
    details: dict       # Additional context for verbose/JSON output
```

### Incremental Backfill Strategy

The original `backfill_team_ids.py` processed ALL 468,970 rows with NULL team_id. Analysis showed:
- Most are historical (~462K from before incremental linker)
- Only ~6,400 are from recent data (staging_id > 25.5M)
- The 6,400 recent rows have NULL game_id (unlinked props issue, not team_id)

Solution: Process only recent rows via staging_id threshold:

```python
# Find staging_id threshold based on days-back
result = conn.execute(text("""
    SELECT COALESCE(MIN(staging_id), 0) as threshold
    FROM raw_player_props_combined
    WHERE snapshot_time >= CURRENT_DATE - :days_back
"""), {"days_back": args.days_back})
```

The 9AM daily stats job hadn't run (computer was off), so we ran it manually and discovered this issue. The incremental approach focuses only on recent data where team_id should be resolvable.

### 2. Prediction Storage Update (G3)

Modified `src/models/daily_runner.py` to populate feature columns:

**New Methods:**
- `_map_features_to_predictions()` — Extracts B1/B2/B3 features from `features_df` and maps them to predictions
- `_get_opponent_abbrevs()` — Returns team abbreviation map using hardcoded `TEAM_ABBREV` dict

**Key Implementation:**
```python
def _map_features_to_predictions(self, predictions_df, features_df):
    """Map feature values to predictions for dashboard insights."""
    # Create (player_id, game_id) -> features lookup
    feature_map = features_df.set_index(["player_id", "game_id"])

    for idx, row in predictions_df.iterrows():
        key = (row["player_id"], row["game_id"])
        if key not in feature_map.index:
            continue
        feat = feature_map.loc[key]

        # B2: Rest/Schedule (same for all stats)
        predictions_df.at[idx, "feat_rest_days"] = feat.get("rest_days")
        predictions_df.at[idx, "feat_is_back_to_back"] = bool(feat.get("is_back_to_back", 0))

        # B3: Stat-specific (varies by row's stat)
        stat = row["stat"]
        if stat in ("pts", "reb", "ast"):
            predictions_df.at[idx, "feat_player_avg_stat_l3"] = feat.get(f"player_avg_{stat}_l3")
            predictions_df.at[idx, "feat_stat_l3_l15_ratio"] = feat.get(f"player_{stat}_l3_l15_ratio")
```

**Defensive Checks Added:**
- Returns early if `opponent_id` column missing
- Returns early if required columns (`player_id`, `game_id`, `stat`) missing

### 3. Insight Generator

Created `dashboard/src/lib/insights.ts`:

**Types:**
```typescript
interface Insight {
  category: 'rest' | 'injury' | 'trend' | 'consistency' | 'average'
  text: string
  sentiment: 'positive' | 'negative' | 'neutral'
}
```

**Functions:**
- `generateInsights(prediction)` — Returns array of insights based on feature values
- `getInsightSummary(insights)` — Returns summary like "2 favorable factors"

**Context-Aware Sentiments:**

The insight generator considers bet direction when determining sentiment:

| Insight | Over Bet | Under Bet |
|---------|----------|-----------|
| L5 avg above line | positive | negative |
| L5 avg below line | negative | positive |
| Hot streak (L3 > L15) | positive | negative |
| Cold stretch (L3 < L15) | negative | positive |

```typescript
// Determine favored bet direction based on edge
const favorsOver = (prediction.over_edge ?? 0) > (prediction.under_edge ?? 0)

if (diff > 3) {
  insights.push({
    category: 'average',
    text: `L5 avg (${avg.toFixed(1)}) is ${diff.toFixed(1)} above line`,
    sentiment: favorsOver ? 'positive' : 'negative'
  })
}
```

## Design Decisions

### Template vs LLM Insights

**Chosen:** Template-based insights

**Rationale:**
- Deterministic and reproducible
- No API latency or cost
- Consistent formatting
- Easy to maintain and extend

### Bet Direction Awareness

**Chosen:** Sentiments consider bet direction

**Rationale:**
- For Under bets, L5 avg below line supports the bet (positive)
- For Over bets, L5 avg above line supports the bet (positive)
- User feedback: "For unders, it shouldnt be a red issue if their stat for the last 5 is under the line"

### Hardcoded Team Abbreviations

**Chosen:** Use same `TEAM_ABBREV` map as dashboard

**Rationale:**
- `teams` table lacks `abbreviation` column
- Dashboard already has reliable mapping
- Consistent between backfill script and daily runner

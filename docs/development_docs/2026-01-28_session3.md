## Context

The model's raw P(over) estimates are catastrophically overconfident (Brier score 0.2705, worse than naive coin-flip 0.2500). The market is well-calibrated (Brier 0.2495). When the model says 84% over, the actual hit rate is 49.1%. The A1 diagnostic proved the model's residuals vs the market have essentially zero predictive signal (r = 0.022).

BL blending is the correct first fix: anchor to the market's well-calibrated prior and only deviate when the model's MC distribution strongly disagrees with the prop line.

## What I Shipped

### 1. New Module: `src/models/black_litterman.py` (~210 lines)

Core BL blending module with two components:

**`BLConfig` dataclass** — Configuration with defaults:
- `tau = 0.05` (global model influence scaling)
- `max_weight = 0.50` (hard cap — never trust model more than market)
- `min_prob = 0.01`, `max_prob = 0.99` (clamping to avoid log(0))

**`BlackLittermanBlender` class** — Four key methods:

1. **`american_to_decimal()`** — Converts American odds to decimal (e.g., -110 → 1.909)
2. **`devig()`** — Removes bookmaker vig via multiplicative normalization. For 2-outcome markets this is equivalent to Shin's method.
3. **`compute_confidence()`** — Z-score based per-prediction confidence:
   ```
   z = |mean(samples) - line| / std(samples)
   confidence = 1 - exp(-0.5 * z²)
   ```
   z=0 → confidence=0 (line at center). z=2 → confidence=0.86 (strong disagreement).
4. **`blend()`** — Log-odds space blending:
   ```
   w = min(tau * confidence, max_weight)
   posterior_logit = market_logit + w * (model_logit - market_logit)
   posterior = sigmoid(posterior_logit)
   ```
5. **`blend_prediction()`** — Full pipeline: devig → model probs → confidence → blend → dict with all diagnostics.

## Design Decisions

### 1. Log-Odds Space (not Linear Probability)

The plan initially described linear blending: `posterior = market + w * (model - market)`. I implemented log-odds space blending instead:

```
posterior_logit = market_logit + w * (model_logit - market_logit)
```

**Rationale:** Linear blending has boundary effects. If market = 0.95 and model = 0.99, linear blend can exceed 1.0 with large w. Log-odds space naturally maps (0,1) → (-∞,+∞), blends linearly there, then maps back via sigmoid. This is the standard BL approach for probability blending.

### 2. Multiplicative Devigging (not Shin Python Package)

Original plan: use the `shin` Python package (Rust-backed). During implementation, `pip install shin` failed because it requires a Rust/Cargo toolchain for native extension compilation.

**Pivot:** Implemented devigging directly in Python using multiplicative normalization: `raw_prob / booksum`. For 2-outcome markets (over/under), this is mathematically identical to Shin's method and the additive method. Eliminates the external dependency entirely.

### 3. Backward Compatibility

BL is disabled by default (`--bl-tau` not set → `bl_blender = None`). The `_calculate_edges()` method has an explicit `if self.bl_blender:` branch. Running without the flag produces identical results to before — zero regression risk.

### 4. Edge Redefinition Under BL

When BL is enabled, the edge calculation changes from:
```
edge = raw_model_prob - raw_implied_prob     # both include vig noise
```
to:
```
edge = posterior_prob - devigged_market_prob  # clean, devigged quantities
```

This is a strictly better edge definition even without the blending — devigged market probs are the correct baseline.

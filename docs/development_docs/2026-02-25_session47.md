# Development Session 47 — 2026-02-25

## Summary

Added US state selector for sportsbook line filtering and clickable line selection for bet sizing in the AnalysisModal. Users can now filter out offshore/unavailable bookmakers based on their state and manually select which sportsbook line to use for Kelly bet sizing calculations.

## Problem

The AnalysisModal's "Sportsbook Lines" section showed lines from all bookmakers including offshore/unregulated ones (Novig, Pinnacle, ProphetX, Bovada) that users can't actually bet on in their state. This also affected the "BEST EDGE" badge and bet sizing calculator — they would recommend bets on books the user couldn't access. Additionally, the bet sizing was locked to the best-edge line with no way to switch to a different bookmaker.

## What Was Built

### 1. US State → Bookmaker Mapping (`sportsbook-availability.ts`)

New utility file with static mapping of ~26 legal US sports betting states to their licensed bookmaker keys.

**Key design decisions:**
- Offshore books (`pinnacle`, `novig`, `prophetx`, `bovada`) excluded from all states
- `fliff` excluded (sweepstakes platform, not a regulated sportsbook)
- `williamhill_us` included alongside `caesars` (rebranded but old DB records exist)
- `bet365` and `unibet` only in states where they actually operate (NJ, CO, OH, PA)
- Used a `MAJOR` constant array for the 8 most common books to reduce duplication
- `getAllowedBookmakers()` returns `null` for "All States" (empty string) — no filtering applied

### 2. State Selector Dropdown (Dashboard Page)

Added a `<select>` dropdown in the dashboard filter bar, before the Model Picks toggle. Shows abbreviated state codes to keep it narrow in the crowded filter bar.

**Data flow:** `localStorage.setItem('user_state', value)` on change → AnalysisModal reads on mount.

### 3. AnalysisModal State Filtering

Three changes to the AnalysisModal:

1. **Read state from localStorage** (read-only, same lazy-init pattern as bankroll)
2. **Filter `processedLines`** with `.filter()` before `.map()` using `getAllowedBookmakers()`
3. **Show filter label** in "Sportsbook Lines" header: "(MI only)"
4. **Updated empty state message** from "No lines available" to "No lines from MI-licensed books" when lines exist but are all filtered out

Changed the display condition from `bookmakerLines.length > 0` to `processedLines.length > 0` to correctly show the filtered-out message.

### 4. Clickable Sportsbook Line Selection

Made line rows interactive for bet sizing:

1. **`selectedLineIndex` state** — defaults to 0 (best edge), resets via `useEffect` when `processedLines` changes
2. **`selectedLine`** replaces `bestEdgeLine` — same positive-edge check but at the user-selected index
3. **Line rows are `<button>` elements** — clicking sets `selectedLineIndex`
4. **Visual feedback:** selected line gets green border + ring, "SIZING" badge appears on selected row
5. **Bet sizing section** uses selected line's odds, model probability, and bookmaker name

## Architecture Decisions

### localStorage for State (not URL param or React context)

Matches the existing pattern used by bankroll, Kelly fraction, and custom Kelly toggle. The state is a user preference, not a URL-navigable filter. It persists across sessions and doesn't need to be shared between components in real-time (AnalysisModal reads it on mount).

### Read-Only in AnalysisModal

The AnalysisModal doesn't allow changing the state — it just reads what was set on the dashboard page. This keeps the modal focused on analysis rather than configuration. Users set their state once on the dashboard and it applies everywhere.

### selectedLineIndex Reset on processedLines Change

Using `useEffect` to reset to 0 when `processedLines` changes ensures the selection doesn't go stale when switching players, changing state filters, or when lines update. The best-edge line (index 0) is always the default.

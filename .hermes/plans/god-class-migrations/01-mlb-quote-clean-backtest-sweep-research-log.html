First implementation slice proposal

Slice 01A — Quote decision policy extraction

  • Create src/backtesting/mlb/quote_decision_policy.py.
  • Create tests/test_mlb_quote_decision_policy.py.
  • Move/copy the current decision-time behavior into explicit functions with names that can survive the larger migration.
  • Update run_mlb_sweep.py to import/use the new functions.
  • Update existing quote-clean line-selection test imports to the new module if practical.
  • Add or update an inventory test only if it can stay small and behavior-preserving in this first commit.

Non-goals for slice 01A

  • No DB queries or Supabase MCP calls.
  • No long MLB backtest sweeps.
  • No feature-store changes.
  • No edge math, BL defaults, threshold, or result schema changes.
  • No hard rejection of unknown quote policies yet; preserve existing fallback unless separately approved.

Suggested first test matrix

  • build_fixed_cutoff_ts(date(2026, 4, 13), "17:30") returns an America/New_York aware datetime.
  • Invalid fixed cutoff strings raise the existing clear ValueError shape.
  • decision_time_for_game(..., policy="fixed_et") returns the fixed cutoff.
  • skip_early_fixed_et returns None when fixed cutoff is after/at commence.
  • relative_to_commence subtracts relative_minutes.
  • slate_or_tminus returns 17:30 ET for normal evening slate and fallback T-minus for early games, matching the current existing regression.
  • NaT/missing commence falls back to fixed cutoff, matching current behavior.

Risks / watch items

  • Timezone comparison risk: current code compares fixed ET datetimes against UTC commence datetimes. Python handles aware datetime comparison, but tests should lock the behavior around early games.
  • Compatibility wrapper risk: if other code imports private helpers from run_mlb_sweep.py, leaving a deprecated wrapper for one phase is safer than breaking hidden callsites.
  • Policy-validation temptation: converting unknown policy fallback into an error is likely correct long-term, but it is behavior-changing and belongs in a later promotion-contract/config phase.
  • Line-ending churn: repo is on a Windows-mounted path; inspect scoped diffs for CRLF-only noise before reviewing implementation.

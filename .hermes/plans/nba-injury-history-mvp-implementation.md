## Behavior

- Require --start-date/--end-date ISO inclusive, bounded <=31 days per run/state. Select exact observed competitive NBA game IDs/dates/team IDs from `team_game_stats` within dates, no props filter. Add optional repeatable --game-id to restrict; verify supplied IDs/date cohort exactly. Limit --max-games default10 maximum100 per invocation; keyset ordered date/game; select limit+1 or otherwise bounded <=100 +sentinel. Retain pending games for resume; never silently call a truncated date range complete. All DB reads read-only with <=15s verified guards. No schema initialization/migration implicit.
- --state-file required. Atomic JSON checkpoint (same-dir temp + replace), source input fingerprint (dates, filters, URL selection; not per-invocation budgets), explicit resume required for existing state, and a simple exclusive sibling lock with clean close. Stale lock error tells user to verify no process then remove only that lock; no lock recovery framework.
- Dry-run default: real bounded SELECTs and PDF requests, zero DB writes. --execute enables remote updates; --mirror-local valid only with --execute. Mode is part of state identity: use separate state for dry-run and execute. --resume uses identical input scope; budgets may change explicitly.
- --max-requests default4 maximum20 counts every HTTP attempt before fetch; --max-games bounds processed games per invocation even on resume. Persist attempted request count and per-report outcome before/after request. No auto retries in an invocation (simpler); retry failed items on explicit resume, never overwrite prior attempt receipts. Persist successful parsed report JSON keyed by URL and digest so resume avoids refetching. No claims that cached parsed JSON is original PDF bytes. Existing parser keeps original HTTP-body SHA. State and cache are local trusted operator artifacts.
- Explicit repeatable --report-url (<=4) OR --report-slot repeatable (<=4) default ['05PM'] creates candidate `https://ak-static.cms.nba.com/referee/injury/Injury-Report_{game_date}_{slot}.pdf`. Validate slots with existing official URL validator; filename is only a locator NOT publication evidence. Support existing accepted formats (inspect parser regex). 404/unsupported/after-cutoff outcomes retained, not invented. Dates plus slots are bounded candidate discovery, NOT archive completeness. No official-index crawler (old season indexes redirect). A single report can cover many games; fetch/cache once per date/URL. Explicit URLs scoped to report game rows by parser/matcher.
- Resolve starts for selected games with existing `resolve_game_timings`; preserve schedule-first authority, unknown conflicts and odds_fallback label. Dry-run uses resolved values without persisting. Execute uses existing `persist_game_timings` on those exact games then freshly verifies timing tuples. Do not claim official scheduled time from odds; no policy changes.
- Load at most 2001 injury rows per exact game date/team set, join/validate team_game_stats to derive unique exact game identity for each `(game_date,nba_team_id)`; do not depend on preexisting injury.game_id. Require player_id and team_id. Existing nonnull wrong game_id is blocked, never overwritten. Null game IDs can be filled only if unique exact date/team fixture and the same row uniquely matches an official report. This minimal identity reconciliation is part of MVP so null-game rows can actually recover. Ambiguous identities stay blocked.
- Reuse `_plan_updates` / `_signature` from scripts/recover_nba_injury_report_times.py without duplicating its matching policy. Recompute from freshly read database rows, no stale manifest plans. To include already-present matches for readback/mirroring, pass shallow row copies with empty source_observations to matching, then compare against actual observations. Keep row identity/precondition in execution payload. Do not insert missing historical statuses or change flat fields/healthy omissions.
- An observation is usable only when verified parser publication <= resolved start minus60 and row matches exactly; count publication matches and pre-cutoff matches separately. Do not attach after-cutoff observations in this MVP (record skipped); if start unknown, retain blocked outcome rather than silently completing the game as usable. No guessed provider clocks.
- Additive JSONB merge per `(row_id,capture_sha)` with guarded identity/status/reason/date/team/player and expected game id; short writable transaction, explicit writable guard <=15s/3s. Prevent stale row updates. Preserve original API captures. Existing identical capture => no-op; existing different content at same capture key => block, don't overwrite. Null game_id can be filled idempotently. Read back exact observation/game/identity from a new read-only transaction before checkpoint success. Crash after commit before checkpoint => recompute/readback on resume and no-op, never assume rollback.
- State stores per-game/report planned/changed/already-present/verified/blocked/error outcomes. Persist after each game; budget/error interruption leaves it resumable. Processed blocked states remain explicit, resume may reevaluate them (within limits); verified execute games should re-read/revalidate rather than just trust old state. Ensure completed games don't starve pending games when max-games is small. Exit0 only selected scope fully accounted without blockers (dry-run labeled plan, never recovered); exit3 remaining due budget; exit4 blocked/errors. Exit2 invalid arguments. No JSON raw credentials/errors.

Copy resolved remote timing receipts using existing persistence function, not local source re-resolution. Missing/local mismatch remains mirror_pending with actionable instruction; NO TRUNCATE, general sync invocation, schema DDL or overwrite unrelated local evidence. Remote success survives mirror failure; resume does not refetch/rewrite remotely merely to retry mirror. Verify local exact rows/timing after commit.

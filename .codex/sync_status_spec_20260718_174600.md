# Implementation Spec: Minimal local DB sync status and scheduling hardening

## Goal
Keep the existing Supabase-to-local sync architecture, add a lightweight persisted status surface, and make the existing local scheduled workflow run in the correct order after Railway morning jobs.

## Files
- `scripts/sync_local_db.py`
- `scripts/run_advanced_scraper.bat`
- `tests/test_sync_local_db_dense_clv.py`

## Requirements
1. Do not create a second sync engine or a DB metadata table.
2. Extend `scripts/sync_local_db.py` to persist a compact JSON journal at `logs/sync/sync_state.json` by default. Allow an optional CLI override if simple.
3. Journal top-level fields should include schema version, started/finished timestamps, overall status, mode/sport, and failed tables. Per-table entries should capture table name, sync strategy/date column, rows selected/copied, remote min/max partition observed for the selected scope when already available, local max partition after successful sync when cheap/already queried, duration, and status/error. Never store URLs or credentials.
4. Add `--status` to print the stored journal in a concise human-readable table without opening either database. If no journal exists, return a clear nonzero result. Do not add checksums or scan tables.
5. Preserve normal sync CLI behavior and existing safety gates.
6. If any table fails, persist partial results and exit nonzero after resources are closed. Successful and dry-run outcomes should exit zero and persist their state.
7. Avoid giant new queries. Reuse values/counts already computed by `sync_table`; a single cheap local MAX on the configured date column after successful copy is acceptable. Do not add post-copy full counts, hashes, or ID-set scans.
8. Refactor return values minimally as needed so `main()` can build the journal. Keep implementation straightforward.
9. Update `scripts/run_advanced_scraper.bat` so the NBA advanced scraper runs first, then `sync_local_db.py`. Capture each exit code independently, log both, and exit nonzero if either fails. Keep existing log directories and secret handling.
10. The Windows Task Scheduler time will be changed externally by the reviewing agent to 10:30 AM; do not invoke `schtasks` from code.
11. Add focused pure tests for status/journal formatting or loading and failure/no-state behavior. Existing dense CLV tests must continue to pass. Tests must not connect to databases.

## Non-goals
- No generalized contract framework.
- No new reconciliation daemon or cron implementation.
- No checksums, full-table post-copy verification, or DB schema changes.
- No Railway scheduler changes.
- No model/feature evaluation changes.
- Do not edit files outside the three listed files.

## GameFlow invariants
- Preserve remote Supabase as canonical and local Postgres as downstream.
- Preserve PK-aware idempotent upserts and the large dense-CLV safety gate.
- Do not print or persist credentials.
- Do not alter modeling, calibration, empirical-CDF, or stats.nba.com/Railway behavior.

## Validation
- `./venv/Scripts/python.exe -m pytest tests/test_sync_local_db_dense_clv.py -q`
- `./venv/Scripts/python.exe -m py_compile scripts/sync_local_db.py`
- `git diff --check -- scripts/sync_local_db.py scripts/run_advanced_scraper.bat tests/test_sync_local_db_dense_clv.py`
- Exercise `--status` against a temporary journal path or pure helper tests without touching either DB.

## Review Criteria
- Scoped diff only.
- Default status command performs zero DB connections.
- Failure returns nonzero and journal never contains secrets.
- Batch order is advanced scrape then sync.
- No unnecessary abstraction or operational overhead.

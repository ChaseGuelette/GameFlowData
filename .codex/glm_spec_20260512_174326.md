# GLM Implementation Spec: MLB pitcher IP feature additions

## Context

We are implementing the first static-feature phase from `brain/Decisions/Pitcher-K-IP-Feature-Source-May01.md`.

Database was checked via isolated sql-runner before this spec:
- `mlb_player_average_pitching` does NOT currently have `min_ip_l5` or similar.
- `mlb_bullpen_daily_status` DOES already have populated source columns:
  - `bullpen_ip_last_3d`
  - `bullpen_pitches_last_3d`
- No `predicted_ip_q25`, `predicted_ip_spread`, or `ip_q25` columns exist in DB.
- No obvious `model_runs` / `model_artifacts` tables exist.

Goal for this task: add static pitcher features only:
1. `pitcher_min_ip_l5` sourced from new `mlb_player_average_pitching.min_ip_l5`.
2. `team_bullpen_ip_last_3d` sourced from pitcher team's own `mlb_bullpen_daily_status.bullpen_ip_last_3d`.
3. `team_bullpen_pitches_last_3d` sourced from pitcher team's own `mlb_bullpen_daily_status.bullpen_pitches_last_3d`.

Do NOT implement the later two-stage predicted-IP model path in this task.
Do NOT add `predicted_ip_q25` or `predicted_ip_spread` yet.
Do NOT touch production deployment config.

## Required changes

### 1) Migration

Create a migration SQL file adding the new local/DB column:

```sql
ALTER TABLE mlb_player_average_pitching
ADD COLUMN IF NOT EXISTS min_ip_l5 FLOAT;
```

Keep it simple. No index needed.

### 2) Full averages backfill script

File: `src/processing/mlb/mlb_populate_averages.py`

Add `min_ip_l5` calculation to `calculate_pitching_averages`.

Known insertion point from exploration:
- `calculate_pitching_averages` computes rolling averages around the loop over `PITCHING_STATS` and `PITCHING_WINDOWS`.
- `avg_ip_l5` is currently produced automatically from `stat = "ip"`, `wname = "l5"`, shifted prior-game values, and rolling mean.

Required behavior:
- Compute minimum IP over the previous 5 starts/games for the pitcher.
- It must preserve temporal integrity: use shifted IP, never current-game IP.
- Use the same grouping key/order as existing rolling pitcher averages.
- Name output column exactly `min_ip_l5`.

Implementation shape should match existing helpers. If the existing code uses `rolling_with_groupby(shifted, group_key, window=5)`, use the same helper with `agg="min"` if supported. If not supported, add minimal helper support for `agg="min"` in the same style as existing `mean` / `std` support.

Add `min_ip_l5` to the insert column set in `insert_pitching_averages`.

Important: if existing insert columns are explicit, add `min_ip_l5`; if dynamically collected, make sure this non-`avg_`/non-`std_` column is included.

### 3) Incremental averages script

File: `src/processing/mlb/mlb_populate_averages_incremental.py`

Add `min_ip_l5` calculation to `calculate_pitching_rolling_for_player`.

Required behavior:
- Use prior-game IP only via `shift(1)`.
- Rolling window 5, `min_periods=1`, min aggregation.
- Column name exactly `min_ip_l5`.

Add `min_ip_l5` to the upsert column set in `upsert_pitching_averages`.

Exploration note:
- `upsert_pitching_averages` currently includes `avg_` and `std_` prefixed columns. `min_ip_l5` will not be included automatically by those prefixes, so include it explicitly.

### 4) Pitcher feature store feature list

Do not remove or reorder unrelated features unnecessarily.

### 5) Training SQL path

File: `src/models/mlb/mlb_feature_store.py`
Function: `_load_single_season_training`

Add rolling-min feature:
- In the outer SELECT, add:
  - `COALESCE(p_avg.min_ip_l5, 0) AS pitcher_min_ip_l5`
- In the LATERAL `p_avg` subquery from `mlb_player_average_pitching`, include `min_ip_l5`.

Add own-team bullpen workload:
- LEFT JOIN `mlb_bullpen_daily_status` using pitcher/game team, not opponent:

```sql
LEFT JOIN mlb_bullpen_daily_status bull
    ON bull.team_id = pgs.team_id
   AND bull.game_date = pgs.game_date
```

- In SELECT add:

```sql
COALESCE(bull.bullpen_ip_last_3d, 0) AS team_bullpen_ip_last_3d,
COALESCE(bull.bullpen_pitches_last_3d, 0) AS team_bullpen_pitches_last_3d,
```

Use a table alias that does not conflict with existing aliases.

### 6) Batch inference/backtesting SQL path

File: `src/models/mlb/mlb_feature_store.py`
Function: `get_features_for_date`

Make parallel changes to training SQL:
- Select `COALESCE(p_avg.min_ip_l5, 0) AS pitcher_min_ip_l5`.
- Include `min_ip_l5` in the LATERAL `p_avg` subquery.
- Add own-team bullpen join on `pgs.team_id` and `pgs.game_date`.
- Select `team_bullpen_ip_last_3d` and `team_bullpen_pitches_last_3d` with COALESCE defaults.

### 7) Single-player inference path

File: `src/models/mlb/mlb_feature_store.py`
Function: `get_player_game_features`

Add bullpen features for the pitcher’s own team:
- After existing weather/game context feature updates, call a new helper:
  - `features.update(self._get_team_bullpen_stats(team_id, game_date))`

Add/update pitcher rolling stats helper:
- Function: `_get_pitcher_rolling_stats`
- Include `min_ip_l5` in the SELECT from `mlb_player_average_pitching`.
- Return `"pitcher_min_ip_l5": float(row.min_ip_l5 or 0)`.
- Ensure no-row default includes `pitcher_min_ip_l5: 0` because it does not match existing `pitcher_avg_` / `pitcher_std_` prefixes.

Add new helper method modeled after batter feature store’s `_get_opposing_bullpen_stats`, but for own team:

```python
def _get_team_bullpen_stats(self, team_id: int, game_date: date) -> dict[str, float]:
    ...
```

Expected return keys:
- `team_bullpen_ip_last_3d`
- `team_bullpen_pitches_last_3d`

Default when no row/error:
- `team_bullpen_ip_last_3d: 0.0`
- `team_bullpen_pitches_last_3d: 0.0`
